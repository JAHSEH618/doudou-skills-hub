# AI 后端开发工程师 · 简历筛选标准（从严版）

岗位核心：寻找深度使用 AI 工具的「进化型」后端开发，善用 AI 实现数倍效率交付，**拒绝传统纯手写搬砖**。按下列六层结构评估，顺序很重要，遇到否决项直接停。

本版为提高门槛后的**从严标准**，与旧版的关键差异：

- **AI coding 工具、SDD/TDD** 两项由「考察 / 加分」升级为**必过能力门槛**，缺一即淘汰；**Agent 应用落地**为最高优先加分项（非门槛，有则强加分）；
- **工龄 > 10 年**、**第一学历专科及以下**：一票否决，任何放宽机制均不适用；
- 通过全部门槛者从 **60 分起评**（**score 超过 60 才进推荐池**，裸 60 不推荐），再按项目经验评定 **初级开发 / 中级 / 高级**，结论行输出 `dir-name-score-等级`。

---

## 一、硬门槛（须全部满足，缺一项即不达标）

- 后端 / 全栈开发方向，工作经验以 2–5 年为理想区间（2 年但潜力突出者可破格，见加分项）
- **工龄 ≤ 10 年（一票否决，不可放宽）**：工龄超过 10 年 → 直接淘汰；大厂 / 强 AI 落地等放宽机制对此**无效**
- **年龄 ≤ 30 岁**：> 30 岁原则上不考虑；命中「放宽机制」者上限放宽至约 35 岁（前提是工龄仍 ≤ 10 年）
- **学历本科及以上（一票否决，不可放宽）**：第一学历为专科（大专）及以下 → 直接淘汰；专升本按第一学历 = 专科处理，原则上同样淘汰
- 计算机基础扎实
- 技术栈聚焦以下三类方向之一：**全栈** / **会 Python** / **会 Java**（「全栈」指能覆盖前后端）
- 熟练掌握 MySQL、Redis
- 是 AI 编程工具的重度使用者（非偶尔尝鲜）

> **第一学历 211 及以上优先**：第一学历为 211 / 985 / 海外名校者**优先推荐**（同等条件下排前、并加分）；非 211 的**本科**不淘汰，仅优先级降低，且可被大厂 / 强 AI 落地经验抵消。专科不参与「优先级」讨论——直接淘汰。

## 二、两大能力门槛（必过；任一缺失 → 直接淘汰）

这是本轮从严筛选的核心。两项**全部是门槛而非加分**，简历上必须有**可指认的证据**（写明工具名 / 框架名 / 项目与落地场景）；只字未提即视为不满足，**直接淘汰，不留到面试再问**。

### 门槛 ①　AI coding 工具实证（区分「进化型」与「传统搬砖」）

- **必须满足**：使用 Cursor / Claude Code / Codex / GitHub Copilot 等**专业 AI 编程工具**写代码，而非把 ChatGPT 网页版、豆包、Kimi、文心一言当搜索引擎用。
- 强度加分（非门槛）：
  - **生产级落地 +8**：AI 生成的代码进过真实生产环境（用户在用的系统），而非仅 Demo、本地测试或学习项目
  - **AI 代码占比 ≥ 70% +6**：核心模式是「人理清逻辑、写需求描述，AI 出代码」，而非仅用于自动补全或写注释

### 门槛 ②　SDD / TDD 工程化

- **必须满足**：对 SDD（规格驱动开发）/ TDD（测试驱动开发）**有了解，且使用过相关工具 / skill**——如 OpenSpec、Superpowers、spec-kit、Kiro 等，或简历中有明确的「先让 AI 写规格书 / 测试用例，再写核心代码」的工作流描述。
- 简历完全无 SDD / TDD / 规格驱动 / 测试驱动 / 相关工具痕迹 → 不满足，淘汰。
- 强度加分（非门槛）：**方法论深度 +6**：规格 / 测试先行的完整工作流在真实项目跑通、有提效数据，或沉淀过团队规范。

## 三、优先方向（加分项，非门槛；命中越靠前越优先）

1. **Agent 应用落地 +10**（最高优先加分）：开发过 AI Agent 应用且**真实落地**——上线生产、有真实用户或业务在用。可指认证据如：LangChain / LangGraph / Dify / Coze / AutoGen / CrewAI / Claude Agent SDK / MCP / Function Calling / 多智能体编排等技术栈 + 明确的业务场景与效果。
   - **不算落地、不得分**：课程 / 毕设项目、本地 Demo、只调了大模型 API 的简单聊天页面、「规划中」的项目。
   - 追加：**复杂度 / 规模 +6**：多智能体协作、MCP / 工具链编排、RAG + Agent 混合架构，或有量化业务效果（调用量、用户量、提效数据）。
   - ⚠️ **不能替代门槛 ①**：「做 Agent 应用」≠「用 AI 写代码」。只有 Agent 经历而无专业 coding 工具实证 → 仍按门槛 ① 淘汰；反过来，缺 Agent 经历只是少这份加分，不淘汰。
2. **金融 / 电商行业 AI 编程经验 +8**（行业契合度）：在银行、支付、保险、证券或电商场景中，用 AI 完成过核心业务开发（非通用 AI 项目）
3. **AI 全栈开发能力 +6**：能在 AI 辅助下独立完成后端 + 前端闭环交付，不依赖专职前端

> 旧版优先方向 ①「TDD/SDD + AI 工程化」已升级为**门槛 ②**，不再作为优先方向。

## 四、加分项

- **第一学历 211 / 985 / 海外名校 +6**：优先推荐信号（非 211 本科不扣分、不淘汰）
- **大厂经历 +5**：一线互联网 / 头部科技公司，并触发「放宽机制」
- 简历中有 AI 提效的具体数据 +4（如「提效 2–3 倍」「一人顶两三人」）
- 有可复用的 Prompt 模板、团队 AI 提效规范等沉淀 +4（团队赋能而非纯个人使用）
- 持续追踪前沿工具（v0、Bolt.new、Claude Code 等），有主动分享 AI 编程心得的记录 +3
- 具备前端开发能力 +3
- 年限较低但 AI 使用深度、自驱力明显优于同龄人 +3

## 五、淘汰信号

- AI 工具只提网页聊天类（ChatGPT 网页版 / 豆包 / Kimi / 文心一言），无专业编程工具 → **一票否决**（通常也过不了门槛 ①）
- 明显的传统纯手写倾向，对 AI 生成生产代码持排斥态度（「Bug 多、不敢上线」）→ **一票否决**
- 简历全是传统开发描述，完全无 AI 工程化、SDD/TDD、提效相关内容 → **一票否决**
- 对前沿工具信息闭塞（只知道用了很久的 GitHub Copilot 也算偏弱）→ 降权 **−6**

## 放宽机制（大厂 / 强 AI 落地 → 只放宽「年龄」与「非 211」）

满足下面**任一**条件即触发「放宽」：

- **大厂经历**：在一线互联网 / 头部科技公司（如 BAT、字节、美团、华为、蚂蚁、京东、网易、拼多多等）或知名外企有正式研发经历。
- **真实强 AI 落地经验**：门槛 ① 的两项强度加分全中（生产级落地 + AI 占比 ≥ 70%），且真实性核验非 🔴 高风险（即不是靠 AI 灌水堆出来的）。

**放宽效果**：

1. **年龄**：上限由 30 岁放宽至约 35 岁（团队可调）。
2. **第一学历**：非 211 **本科**的优先级劣势予以抵消，视同满足学历优先项，不再因学历降序。

**不可放宽（从严版红线）**：**工龄 > 10 年**、**专科及以下学历**、**两大能力门槛（① coding 工具 / ② SDD/TDD）**、淘汰信号、🔴 灌水夸大——以上任何一项都不因大厂 / 强 AI 落地而松动。放宽**仅**作用于「年龄 ≤ 30」与「非 211 本科的优先劣势」两项。

## 判定逻辑（评分表与人工结论通用）

按以下规则得出最终建议（自上而下，命中即停）：

| 条件 | 结论 |
|---|---|
| **工龄 > 10 年** | 直接淘汰（一票否决，不可放宽） |
| **第一学历专科（大专）及以下** | 直接淘汰（一票否决，不可放宽） |
| 命中任一**一票否决淘汰信号**（工具降级 / 排斥上线 / 全传统无 AI） | 建议淘汰 / 谨慎复核 |
| 其他**硬门槛**缺项（技术栈不属 全栈 / Python / Java、基础薄弱等） | 不达标 |
| **年龄 > 30 岁** 且未触发放宽（无大厂 / 无强 AI 落地） | 不达标（年龄门槛） |
| **门槛 ①** 不满足：无专业 AI coding 工具实证 | 淘汰（疑似传统开发） |
| **门槛 ②** 不满足：无 SDD/TDD 了解与相关工具使用证据 | 淘汰 |
| **全部门槛通过** | 起评 60 分，加强度 / 优先方向 / 背景加分、减扣分得 score；按「等级评定」给 初级开发 / 中级 / 高级；**score > 60 入推荐池**（裸 60 不推荐） |
| 通过门槛但 score ≤ 60（仅裸过门槛、无任何加分，或被 🔴 灌水等扣分拉低） | 边缘：不入主推荐表，明细中列出（被扣分者面试重点核验） |

> **第一学历优先排序**：判定与分数相同时，第一学历 211 / 985 / 海外名校者**优先推荐 / 排前**；非 211 本科不降档，仅并列时靠后（触发放宽可抵消）。

> **第六层 · 真实性核验（独立层）**：得出上述判定后，再按 `ai-writing-integrity-check.md` 检测简历是否被 AI 灌水，输出「美化经历风险」🟢低 / 🟡中 / 🔴高。该层不改变门槛判定，但 🔴 高风险**扣 12 分并标记面试重点核验**；高 AI 痕迹但硬细节充分（仅润色）**不扣分**。

## 等级评定（通过者必做：初级开发 / 中级 / 高级）

仅对「通过全部门槛」的候选人评定。依据是**项目经验质量**——复杂度、独立负责程度、落地深度；工作年限仅作参考、不作决定因素。等级与 score 相互独立（通常正相关，但**不要由分数倒推等级**）。

| 等级 | 项目经验判据（满足大部分即归档） |
|---|---|
| **高级** | 主导过完整系统或核心业务模块的架构设计与上线；SDD/TDD 已成默认工作流（规格 / 测试先行成体系）；有带人、定规范、团队 AI 赋能的痕迹；能讲清技术取舍；如有 Agent 应用，已在生产环境稳定运行且有量化业务效果 |
| **中级** | 能独立负责模块级的开发与上线；SDD/TDD 用过相关工具、流程能跑通但未成体系；如有 Agent 应用，有真实落地但复杂度 / 规模一般；项目叙述以「独立完成某块」为主 |
| **初级开发** | 以参与为主、在指导下完成开发；两大门槛达标但深度有限（SDD/TDD 仅初步使用）；Agent 经验缺失或仅 Demo 级；项目叙述以「参与 / 协助」为主 |

参考年限（仅校准用，证据优先）：高级常见 5–10 年，中级常见 3–5 年，初级开发常见 ≤ 3 年。工龄 > 10 年已在硬门槛淘汰，故「高级」不会超过 10 年工龄。

## 分值建议（可按团队松紧调整）

分层否决逻辑优先于分数；**任一门槛未过 → 不计分**，直接按判定逻辑出局。

- **基础分**：硬门槛 + 两大能力门槛全部通过 → **起评 60 分**（推荐线为「**超过 60**」：裸过门槛的 60 分不推荐，至少还须命中一项强度 / 加分才入推荐池；扣分项会把可疑者拉下去）
- 门槛 ① 强度：生产级落地 +8；AI 代码占比 ≥ 70% +6
- 门槛 ② 强度：SDD/TDD 方法论深度（完整工作流 + 提效数据 / 团队规范）+6
- 优先方向：Agent 应用落地 +10（复杂度 / 规模再 +6；仅 Demo 不得分）；金融 / 电商 +8；AI 全栈 +6
- 背景加分：第一学历 211 / 985 / 海外名校 +6；大厂经历 +5（并触发放宽）
- 其他加分：提效数据 +4；Prompt / 团队规范沉淀 +4；前沿工具追踪 +3；前端能力 +3；低年限高潜 +3
- 扣分：信息闭塞 −6；真实性核验 🔴 高 −12（🟡 中不扣分、标记面试核验；🟢 低 0）
- **总分上限 100**（溢出按 100 计），下限 0

## 面试现场提问对照（供面试官参考）

筛进面后，下面七题用于核验。原则：第 1–4 题对应硬性要求（专业工具、SDD/TDD、AI 占比、纠错能力），**任一答崩 → 简历所写存疑，按灌水处理**；第 5–7 题为加分核验（第 5 题对简历写了 Agent 经历者必问，答崩则该项加分作废并疑灌水）。

1. **核心工具与生产落地**（门槛 ①）：常用哪款 AI 编程工具？AI 生成的代码有直接上线生产吗？
   - 合格：说得出专业工具（Cursor/Claude Code/Codex/Copilot），明确「有 / 经常上线」。
   - 淘汰：只提网页聊天工具；或「Bug 多、只敢本地测、不敢上线」。
2. **SDD/TDD 工程化**（门槛 ②）：有没有用 AI 结合 SDD/TDD 的实战？用过什么工具，流程怎么走？
   - 合格：能说出 OpenSpec / Superpowers / spec-kit 等工具或「先规格 / 测试后代码」的完整流程，并对应到真实项目。
   - 淘汰：听不懂 SDD/TDD，或说不出任何工具与流程——简历相关描述按灌水处理。
3. **AI 生成代码比例**（门槛 ① 强度）：AI 代码占比多少？还大量纯手写吗？
   - 合格：70%+，「不手写机械代码，自己理逻辑写需求，剩下交给 AI」。
   - 淘汰：10%–30%，或觉得 AI 写的不能用、还是习惯手写。
4. **对 AI 报错 / 幻觉的处理**：让 AI 改 Bug 连续 3 次都错，怎么办？
   - 合格：重写 Prompt、缩小范围喂精准上下文和日志、检查前置规格是否写错。
   - 淘汰：「那就不管 AI 了，自己手写排查」。
5. **Agent 应用落地复述**（优先方向 ① · 加分核验，简历写了 Agent 经历者必问）：讲一个你落地的 Agent 应用——业务场景、编排框架、工具调用 / MCP、上下文与记忆怎么管、上线后踩过什么坑？
   - 加分成立：细节能自然展开，有真实业务场景、线上问题与解决过程。
   - 加分作废：只会「调了下 API」「用 Dify 拖了个流程」，说不出业务效果与线上问题——判为 Demo 级；若简历重点渲染 Agent 经历，按灌水处理。
6. **AI 全栈提效**（加分）：AI 辅助下能独立完成前端到什么程度？
   - 加分：「前端页面、前后端对接都能独立搞定，一个人全量交付全栈」。
   - 偏弱：「我纯后端，AI 生成的前端样式问题多，得专业前端改，我做不了」。
7. **前沿工具敏锐度**（加分）：除了 Cursor，最近关注 / 试过哪些新 AI 编程工具？
   - 加分：如数家珍（Claude Code、v0、Bolt.new 等），有强好奇心。
   - 偏弱：半天说不上来，或只知道老牌 GitHub Copilot。
