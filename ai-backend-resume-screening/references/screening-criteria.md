# AI 后端开发工程师 · 简历筛选标准（从严版）

岗位核心：寻找深度使用 AI 工具的「进化型」后端开发，善用 AI 实现数倍效率交付，**拒绝传统纯手写搬砖**；同时**不招 AI 应用工程师**——要的是**传统业务项目借助 AI 提效**的人，不是招进来做智能体的人，RAG / 大模型应用 / Agent 开发经历只能作加分（主业即此类 → 画像错位淘汰，见第五节）。按下列六层结构评估，顺序很重要，遇到否决项直接停。

本版为提高门槛后的**从严标准**，与旧版的关键差异：

- **AI coding 工具、SDD/TDD** 两项由「考察 / 加分」升级为**必过能力门槛**，缺一即淘汰；**Agent 应用落地**为最高优先加分项（非门槛，有则强加分）；
- **画像校验**：项目经验**主体**为 RAG / 大模型应用 / Agent 开发、传统业务系统后端单薄者 → **画像错位，一票否决**（见第五节）；此类经历仅在传统后端主体之上作加分；
- **工龄 > 10 年**、**无本科学历（最高学历专科及以下）**：一票否决，任何放宽机制均不适用；
- **门槛 ② 按证据强度分 A / B / C 三档**，C 档淘汰、B 档总分封顶 85（见第二节）；
- 全局适用 **证据规则**（第零节）：加分必须有可引用原句，**禁止推断加分**；
- 通过全部门槛者从 **60 分起评**（**score 超过 60 才进推荐池**，裸 60 不推荐），再按项目经验评定 **初级开发 / 中级 / 高级**，结论行输出 `dir-name-score-等级-门槛②档位`。

## 零、证据规则（全局适用，优先于其他所有条款）

这一节是为了防止「读出了简历里没写的东西」。**每次给分或判过之前，先过一遍这五条。**

1. **直接证据原则**：每一项门槛判定与每一分加分，都必须能在简历正文 / PDF 批注 / 补充材料中找到**一句可直接引用的原文**。写不出这句引用 → 该项不成立、不给分。评估记录里应能贴出原句。
2. **禁止推断加分（最常犯的错）**：两个各自为真的事实，其合取**不构成第三个事实**。
   - ❌「他在银行做核心系统」+「他会用 Claude Code」⇒「他用 AI 做了银行核心系统」——除非有一句话把两者绑在同一项目上，否则**不得**给行业 × AI 类加分。
   - ❌「他在职期间项目是生产系统」+「他用 AI 编码」⇒「AI 代码上了生产」——生产级落地 +8 需要「AI 生成 / 辅助的代码进入生产」这层意思被明确表达。
3. **禁止一证多用**：同一段证据只能支撑一个加分项。用「全栈交付」拿了 AI 全栈 +6，就不能再用同一句拿前端能力 +3。
4. **自报数字须与正文互证**：AI 占比、提效倍数等自报数字，若**简历正文的项目描述里找不到任何 AI 参与的具体痕迹**（无工具名、无 AI 环节、无 AI 产出物），则该数字判为「**待核验**」：
   - 其支撑的强度加分（生产落地 +8、占比 ≥70% +6）**减半计入**；
   - 真实性评级**至少 🟡 中**，并在明细标注「自报占比与正文无互证」；
   - 且**不得**用于触发放宽机制（见「放宽机制」）。
5. **自我弱化即降档——但先分清「没做到」和「做过之后弃用」**：
   - **能力型弱化 → 按弱化后水平判**：「没有完全按规范」「半成品」「只是尝试过」「了解过」「用得不多」「还停留在…」，一律按其**自我弱化后的水平**判定，不按其想表达的理想状态判定。诚实的人不该被奖励性拔高，但也不该被替他补全。
   - **判断型弃用 ≠ 自我弱化，不得据此降档**：「superpowers 用过一段时间，现在模型能力变强后就有些冗余了」「某版本出来之后就不用了，会降速」——这类表述**预设了「用到足以判断收益」**，是对模型与工具边界的判断力，属正向信号，恰恰不是能力不足。它只能证明「当下不用这个工具」，证明不了「当下没有规格 / 测试先行」。判法见门槛 ② C 档「判断型弃用」条：改问**弃用前说不说得清怎么用、弃用后拿什么替代先行顺序**。

> 落地提示：这五条对应的真实误判都发生过——把"在银行 + 会用 AI"推成"用 AI 做银行系统"、把"全栈"和"前端证书"双计、把"AI 占比 95% 但正文零 AI 痕迹"当强落地用于放宽。写标准时觉得多余，实筛时全会踩。

## 一、硬门槛（须全部满足，缺一项即不达标）

- 后端 / 全栈开发方向，工作经验以 2–5 年为理想区间（2 年但潜力突出者可破格，见加分项）
- **工龄 ≤ 10 年（一票否决，不可放宽）**：工龄超过 10 年 → 直接淘汰；大厂 / 强 AI 落地等放宽机制对此**无效**
- **年龄 ≤ 33 岁**：> 33 岁原则上不考虑；命中「放宽机制」者上限放宽至约 35 岁（前提是工龄仍 ≤ 10 年）
- **学历本科及以上（一票否决，不可放宽）**：最高学历为专科（大专）及以下（未取得本科）→ 直接淘汰；**非全日制本科可接受**——专升本、自考、成考、函授、网络教育取得的本科均算过门槛，不按专科淘汰
- 计算机基础扎实
- 技术栈聚焦以下三类方向之一：**全栈** / **会 Python** / **会 Java**（「全栈」指能覆盖前后端）
- 熟练掌握 MySQL、Redis
- 是 AI 编程工具的重度使用者（非偶尔尝鲜）
- **深圳候选人专项要求**：行业经验须包含**跨境电商**（如跨境支付、跨境物流、多币种结算、海关通关系统、跨境供应链、跨境合规等）。简历中行业经验未体现跨境电商 → 不达标（此项仅适用于深圳候选人，非深圳候选人忽略）

> **第一学历 211 及以上优先**：第一学历为 211 / 985 / 海外名校者**优先推荐**（同等条件下排前、并加分）；非 211 的**本科**（含非全日制本科）不淘汰，仅优先级降低，且可被大厂 / 强 AI 落地经验抵消。无本科（纯专科）不参与「优先级」讨论——直接淘汰。

## 二、两大能力门槛（必过；任一缺失 → 直接淘汰）

这是本轮从严筛选的核心。两项**全部是门槛而非加分**，简历上必须有**可指认的证据**（写明工具名 / 框架名 / 项目与落地场景）；只字未提即视为不满足，**直接淘汰，不留到面试再问**。

### 门槛 ①　AI coding 工具实证（区分「进化型」与「传统搬砖」）

- **必须满足**：使用 Cursor / Claude Code / Codex / GitHub Copilot 等**专业 AI 编程工具**写代码，而非把 ChatGPT 网页版、豆包、Kimi、文心一言当搜索引擎用。
- 强度加分（非门槛）：
  - **生产级落地 +8**：AI 生成的代码进过真实生产环境（用户在用的系统），而非仅 Demo、本地测试或学习项目
  - **AI 代码占比 ≥ 70% +6**：核心模式是「人理清逻辑、写需求描述，AI 出代码」，而非仅用于自动补全或写注释

### 门槛 ②　SDD / TDD 工程化（**按证据强度分 A / B / C 三档**）

这是从严版真正的分水岭。门槛 ① 因为 HR 前置问卷的存在，通过率天然很高；**能不能筛出人，全看门槛 ② 判得严不严**。旧版「有了解且使用过工具 / skill，**或**有明确工作流描述」这个「或」分支过宽，实筛中会把「半成品 SDD」「先定义要做什么再实现」这类通用话术也放进来。故改为三档判定，**先定档，再判过**。

判定顺序：先找证据 → 定档 → A/B 过、C 淘汰。**定档结论必须写进结论行与 checked.md。**

#### A 档　工具级实证（过；可给深度加分 +6；总分不封顶）

同时满足两条：

1. **点名** SDD/TDD 工程化工具或 skill：OpenSpec、Superpowers、spec-kit、Kiro、ecc、自研 spec 框架等；
2. 说明**在具体项目里怎么用**——给得出命令、阶段、产出物或角色分工中的至少两样。

> 典型合格表述：「用 OpenSpec 的 `/opsx:propose` 把需求固化为含验收场景的规范文档和任务清单，让规范成为唯一事实来源；再由 Superpowers 执行红灯-绿灯-重构，先写失败测试、再写最少代码通过、最后安全重构」「先用 OpenSpec 产出接口定义与业务校验规则文档，再通过 Superpowers 调度子 Agent 开发，强制先写测试用例再实现业务代码」。

#### B 档　流程级描述（过；**不给深度加分**；**总分封顶 85**）

无工具名，但给出**可复述的执行序列**，且序列中「规格或测试**先于**代码」这一先后顺序**明确、无歧义**。

> 典型合格表述：「TDD：先写测试，再让 AI 写代码；SDD：先写结构化需求文档，再让 AI 按文档生成代码」「给它定好需求描述 → 它生成规格文档 → 我审查增删、对齐需求 → 再要它生成代码 → 审查代码」「开发前通过 AI 生成全场景单元测试用例与边界异常用例，再写业务代码」。

封顶理由：B 档只有口头承诺，缺工具与产出物这层可验证物证。封顶是道**安全阀**——挡住「Agent 加分拉满 + SDD 只有一句口头描述」的人冲到 90+，与工具级实证者平起平坐。

> ⚠️ **不要指望封顶制造分数分离**。实测（2026-07-20 至 08-05，42 位通过者）：A 档 25 人中仅 5 人 ≥86，多数落在 66–85；B 档 24 人中仅 3 人触到 85 上限。**两档分数区间大面积重叠是正常的**——A 档只保证有工具实证，若无 Agent 落地、无大厂、无 211，A 档拿 70 分很常见。**档位靠结论行的档位字段承载，不靠分数**；推荐表按档位分区呈现（见 SKILL.md「输出格式」），不要跨区按分数混排。

#### C 档　口头泛述 / 顺序错位 / 概念混淆（**淘汰**）

命中下列**任一**即判 C 档，直接淘汰，不留到面试再问：

- **自我弱化（能力型）**：「没有完全按规范去做」「先做半成品的 SDD」「只是尝试过」「了解过 / 有了解」「用得不多」「还停留在大模型辅助编程」；
- **⚠️ 判断型弃用不在此列，弃用表述本身一律不判 C**：「superpowers 用过一段时间，模型能力变强后就冗余了」「.6 出来之后 superpower 就不用了会降速」——这是用过之后的取舍，不是没做到，**不许当自我弱化处理**。改按两问定档：
  1. **弃用前说得清怎么用吗**——命令 / 阶段 / 产出物，或该工具当时解决的**具体失效模式**（如「模型弱时把需求细化，避免任务描述不够细致时 AI 走偏」）。说得清 → 工具级实证曾经成立，可计入 A 档第 2 条；只有「以前用过、现在不用了」而零细节 → 不构成实证，但也不因此判 C。
  2. **弃用后拿什么替代先行顺序**——模型自带 plan / 计划模式、CLAUDE.md / AGENTS.md 约束、自写规格文档、CI 测试门禁等。说得出具体替代 → 按**替代方案本身**的证据强度定 A / B；说不出、或现状描述里规格与测试的时点仍含糊 → 判 C，且结论行**必须写「弃用后无先行顺序替代」，不得写「自我弱化」**——理由写错会把同型的好候选人一起误杀。
- **顺序错位（最隐蔽）**：测试出现在编码**之后**——「先做个原型出来，再按需求点一个个进行测试」「开发完让 AI 补单测」。测试后置是常规做法，不是 TDD；
- **概念混淆**：把 SDD 理解为「**系统设计文档 / 详细设计文档**」（System Design Document）而非规格驱动开发（Spec-Driven Development）。看到候选人自己括注「SDD（系统设计文档）」，直接判 C；
- **通用话术**：「先定义要做什么再围绕这个实现并验证」「先梳理需求再开发」——这类描述适用于任何开发流程，不含 SDD/TDD 的任何特征信息；
- **只谈认知不谈实践**：只说 SDD/TDD 是什么、适合什么场景，不说自己在哪个项目怎么做的；
- **只有工具名没有用法**：仅在技能栏罗列「Superpowers / OpenSpec」而正文无任何使用描述——工具名是关键词堆砌，不是实证。

#### 深度加分（仅 A 档可得）

**方法论深度 +6**：在 A 档基础上，另需满足「完整工作流在真实项目跑通」**且**（「有提效数据」**或**「沉淀过团队规范 / skill / rules」）。只有工作流、没有数据也没有团队沉淀 → 不给。

> ⚠️ 反面校准（这些人历史上被淘汰过，是本档位的尺子，新候选人不强于他们就同样淘汰）：
> - 「Claude Code/Cursor/Codex 约 80% 编码有工作描述，但 SDD 仅解释适合需求迭代，未给出项目级规格或测试先行的完整执行闭环」→ C 档淘汰；
> - 「Claude Code 有实际工作辅助开发场景，但本人明确 TDD 使用较少，SDD 仅体现 Claude.md 和 Superpowers 插件，缺规格或测试先行完整闭环」→ C 档淘汰（**注意：提到了 Superpowers 也照淘**，因为只有工具名、没有先行顺序的执行描述）。

## 三、优先方向（加分项，非门槛；命中越靠前越优先）

1. **Agent 应用落地 +10**（最高优先加分）：开发过 AI Agent 应用且**真实落地**——上线生产、有真实用户或业务在用。可指认证据如：LangChain / LangGraph / Dify / Coze / AutoGen / CrewAI / Claude Agent SDK / MCP / Function Calling / 多智能体编排等技术栈 + 明确的业务场景与效果。
   - **不算落地、不得分**：课程 / 毕设项目、本地 Demo、只调了大模型 API 的简单聊天页面、「规划中」的项目。
   - 追加：**复杂度 / 规模 +6**：多智能体协作、MCP / 工具链编排、RAG + Agent 混合架构，或有量化业务效果（调用量、用户量、提效数据）。
   - ⚠️ **不能替代门槛 ①**：「做 Agent 应用」≠「用 AI 写代码」。只有 Agent 经历而无专业 coding 工具实证 → 仍按门槛 ① 淘汰；反过来，缺 Agent 经历只是少这份加分，不淘汰。
   - ⚠️ **加分的前提是画像正确**：本项加的是「传统业务后端**顺手**做出了 Agent 落地」，不是招 Agent 开发工程师。整份简历以 RAG / 大模型应用 / Agent 开发为主体、传统业务后端单薄者，**不适用本加分**——按第五节「画像错位」一票否决。同一段经历不能既构成画像错位又拿落地加分。
2. **金融 / 电商行业 × AI 编码 +8**（行业契合度）：**在同一个项目上**同时满足两个条件——① 该项目属于银行、支付、保险、证券或电商业务系统；② 候选人**用 AI 编程工具产出了该系统的业务代码**。
   - ⚠️ 本项最容易被推断加分污染，务必按第零节第 2 条核验。需要一句话把「行业项目」和「AI 编码」绑在一起，例如「AI 批量生成基础 CRUD、数据同步脚本，人工完成金融核心逻辑重构」「引入 AI 工具辅助单元测试和异常定位，缩短规则开发周期」。
   - **不算命中**：只是「在电商公司做过 AI 功能」（那是开发 AI 应用，属优先方向 ①，不重复计）；只是「在银行做过传统开发」＋另一处提到会用 AI（分属两个时期 / 两个项目，禁止跨项目合取）。
3. **AI 全栈开发能力 +6**：能在 AI 辅助下独立完成后端 + 前端闭环交付，不依赖专职前端。**与加分项「具备前端开发能力 +3」互斥**（前者已含后者），只取其一。

> 旧版优先方向 ①「TDD/SDD + AI 工程化」已升级为**门槛 ②**，不再作为优先方向。

## 四、加分项

- **第一学历 211 / 985 / 海外名校 +6**：优先推荐信号（非 211 本科不扣分、不淘汰）
- **大厂经历 +5**：一线互联网 / 头部科技公司（BAT、字节、美团、华为、蚂蚁、京东、网易、拼多多，及得物、叮咚买菜、喜马拉雅等知名互联网公司），并触发「放宽机制」。**外派 / 驻场 / 外包到大厂不计**——用人单位是外包公司即不给分，但可在明细注明驻场经历。
- 简历中有 **AI 提效**的具体数据 +4（如「提效 2–3 倍」「返工率下降 70%」「一次生成通过率 40%→85%」）。⚠️ 必须是 **AI 带来的**提效；「接口耗时 5s→200ms」「单测覆盖率 40%→80%」这类**工程优化数据不算**，那是本职工作成果。
- 有可复用的 Prompt 模板、团队 AI 提效规范等沉淀 +4：须是**团队级**——他人在用、写进团队规范、或已开源。**纯个人 skills 库不给**（「自己去 GitHub 找 skill 用」属个人使用）。
- 持续追踪前沿工具 +3：除主力工具外，**另外**说得出 ≥2 个当年新工具 / 新生态（v0、Bolt.new、OpenCode、OpenClaw、Qoder、Trae、CodeBuddy、MCP 生态等），或有主动分享 AI 编程心得的记录。**只列 Claude Code / Cursor / Copilot 三件套不给**——那是主力工具，不是前沿追踪。
- 具备前端开发能力 +3（与「AI 全栈 +6」互斥，取高者）。**培训证书不构成实证**，需项目中有前端产出。
- 年限较低但 AI 使用深度、自驱力明显优于同龄人 +3

## 五、淘汰信号

- AI 工具只提网页聊天类（ChatGPT 网页版 / 豆包 / Kimi / 文心一言），无专业编程工具 → **一票否决**（通常也过不了门槛 ①）
- 明显的传统纯手写倾向，对 AI 生成生产代码持排斥态度（「Bug 多、不敢上线」）→ **一票否决**
- 简历全是传统开发描述，完全无 AI 工程化、SDD/TDD、提效相关内容 → **一票否决**
- **画像错位（AI 应用工程师 ≠ 本岗位）→ 一票否决**：岗位要的是「**传统业务项目借助 AI 提效**」的后端，不是招人进来做智能体。项目经验**主体**为 RAG / 知识库问答 / 大模型应用开发（Prompt 工程平台、模型微调、LLM 网关等）/ Agent 开发，而传统业务系统（交易、订单、支付、供应链、ERP、内部系统等）后端经验缺失或明显单薄 → 淘汰。大模型算法方向（预训练、微调、推理优化、算法研究）离岗位更远，同判。
  - **判「主体」，不判关键词命中**：简历出现 RAG / LangChain / Agent 字样不等于画像错位——主体是传统业务后端、其中一两个项目做过 Agent / RAG，恰是优先方向 ① 的加分对象。要看**近年项目列表里传统业务系统占多少**：全部或绝大多数项目是大模型应用 → 错位淘汰；传统业务为主、穿插一两个 → 正常加分。
  - **强信号（可直接引用的原句）**：求职意向 / 自我评价写「AI 应用工程师」「大模型应用开发方向」「Agent 开发工程师」；技能栏以 LangChain / RAG / 微调为主而后端基础栈（MySQL / Redis / 业务框架）淡化或缺失。
  - 拿不准时回到岗位画像问一句：**这个人入职后，是用 AI 提效做业务系统，还是只会继续做智能体？** 简历给不出前者的证据 → 错位。
- 对前沿工具信息闭塞（只知道用了很久的 GitHub Copilot 也算偏弱）→ 降权 **−6**

## 放宽机制（大厂 / 强 AI 落地 → 只放宽「年龄」与「非 211」）

满足下面**任一**条件即触发「放宽」：

- **大厂经历**：在一线互联网 / 头部科技公司（如 BAT、字节、美团、华为、蚂蚁、京东、网易、拼多多等）或知名外企有**正式**研发经历（外派 / 驻场 / 外包不算）。
- **真实强 AI 落地经验**：门槛 ① 的两项强度加分全中（生产级落地 + AI 占比 ≥ 70%），且真实性核验非 🔴 高风险，**且自报占比与正文互证**——简历正文的项目描述中须有 AI 参与的具体痕迹（工具名 / AI 环节 / AI 产出物）。
  - ⚠️ 「技能栏写着会用 Claude Code、自报占比 95%，但全部项目描述都是纯传统开发、零 AI 痕迹」→ 按第零节第 4 条判为「待核验」，**不触发放宽**。这类候选人若年龄 > 33，直接按年龄门槛不达标处理。

**放宽效果**：

1. **年龄**：上限由 33 岁放宽至约 35 岁（团队可调）。
2. **第一学历**：非 211 **本科**的优先级劣势予以抵消，视同满足学历优先项，不再因学历降序。

**不可放宽（从严版红线）**：**工龄 > 10 年**、**无本科学历（最高学历专科及以下）**、**深圳候选人缺跨境电商经验**、**两大能力门槛（① coding 工具 / ② SDD/TDD）**、淘汰信号、🔴 灌水夸大——以上任何一项都不因大厂 / 强 AI 落地而松动。放宽**仅**作用于「年龄 ≤ 33」与「非 211 本科的优先劣势」两项。

## 判定逻辑（评分表与人工结论通用）

按以下规则得出最终建议（自上而下，命中即停）：

| 条件 | 结论 |
|---|---|
| **工龄 > 10 年** | 直接淘汰（一票否决，不可放宽） |
| **无本科学历（最高学历专科及以下；非全日制本科 / 专升本算过门槛）** | 直接淘汰（一票否决，不可放宽） |
| **深圳候选人** 且行业经验不含跨境电商 | 不达标（深圳专项要求，不可放宽） |
| 命中任一**一票否决淘汰信号**（工具降级 / 排斥上线 / 全传统无 AI / **画像错位：项目主体为 RAG / 大模型应用 / Agent 开发**） | 建议淘汰 / 谨慎复核 |
| 其他**硬门槛**缺项（技术栈不属 全栈 / Python / Java、基础薄弱等） | 不达标 |
| **年龄 > 33 岁** 且未触发放宽（无大厂 / 无强 AI 落地） | 不达标（年龄门槛） |
| **门槛 ①** 不满足：无专业 AI coding 工具实证 | 淘汰（疑似传统开发） |
| **门槛 ② 判为 C 档**（口头泛述 / 测试后置 / SDD 概念混淆 / 只有工具名无用法 / 能力型自我弱化 / 弃用后无先行顺序替代） | 淘汰 |
| **全部门槛通过** | 起评 60 分，加强度 / 优先方向 / 背景加分、减扣分得 score；**门槛 ② 为 B 档者总分封顶 85**；按「等级评定」给 初级开发 / 中级 / 高级；**score > 60 入推荐池**（裸 60 不推荐） |
| 通过门槛但 score ≤ 60（仅裸过门槛、无任何加分，或被 🔴 灌水等扣分拉低） | 边缘：不入主推荐表，明细中列出（被扣分者面试重点核验） |

> **第一学历优先排序**：判定与分数相同时，第一学历 211 / 985 / 海外名校者**优先推荐 / 排前**；非 211 本科不降档，仅并列时靠后（触发放宽可抵消）。

> **第六层 · 真实性核验（独立层）**：得出上述判定后，再按 `ai-writing-integrity-check.md` 检测简历是否被 AI 灌水，输出「美化经历风险」🟢低 / 🟡中 / 🔴高。该层不改变门槛判定，但 🔴 高风险**扣 12 分并标记面试重点核验**；高 AI 痕迹但硬细节充分（仅润色）**不扣分**。

## 等级评定（通过者必做：初级开发 / 中级 / 高级）

仅对「通过全部门槛」的候选人评定。依据是**项目经验质量**——复杂度、独立负责程度、落地深度；工作年限仅作参考、不作决定因素。等级与 score 相互独立（通常正相关，但**不要由分数倒推等级**）。

| 等级 | 项目经验判据（满足大部分即归档） |
|---|---|
| **高级** | 主导过完整系统或核心业务模块的架构设计与上线；SDD/TDD 已成默认工作流（规格 / 测试先行成体系）；有带人、定规范、团队 AI 赋能的痕迹；能讲清技术取舍；如有 Agent 应用，已在生产环境稳定运行且有量化业务效果 |
| **中级** | 能独立负责模块级的开发与上线；SDD/TDD 用过相关工具、流程能跑通但未成体系；如有 Agent 应用，有真实落地但复杂度 / 规模一般；项目叙述以「独立完成某块」为主 |
| **初级开发** | 以参与为主、在指导下完成开发；两大门槛达标但深度有限（SDD/TDD 仅初步使用）；Agent 经验缺失或仅 Demo 级；项目叙述以「参与 / 协助」为主 |

参考年限（仅校准用，证据优先）：高级常见 5–10 年，中级常见 3–5 年，初级开发常见 ≤ 3 年。工龄 > 10 年已在硬门槛淘汰，故「高级」不会超过 10 年工龄。

## 分值建议（可按团队松紧调整）

分层否决逻辑优先于分数；**任一门槛未过 → 不计分**，直接按判定逻辑出局。

- **基础分**：硬门槛 + 两大能力门槛全部通过 → **起评 60 分**（推荐线为「**超过 60**」：裸过门槛的 60 分不推荐，至少还须命中一项强度 / 加分才入推荐池；扣分项会把可疑者拉下去）
- 门槛 ① 强度：生产级落地 +8；AI 代码占比 ≥ 70% +6（**自报数字无正文互证 → 各减半**，见第零节第 4 条）
- 门槛 ② 强度：SDD/TDD 方法论深度 +6（**仅 A 档可得**，且须「完整工作流跑通」＋「提效数据 或 团队沉淀」）
- 优先方向：Agent 应用落地 +10（复杂度 / 规模再 +6；仅 Demo 不得分）；金融 / 电商 × AI 编码 +8；AI 全栈 +6
- 背景加分：第一学历 211 / 985 / 海外名校 +6；大厂经历 +5（并触发放宽；外派驻场不计）
- 其他加分：AI 提效数据 +4；团队级 Prompt / 规范沉淀 +4；前沿工具追踪 +3；前端能力 +3（与 AI 全栈互斥）；低年限高潜 +3
- 扣分：信息闭塞 −6；真实性核验 🔴 高 −12（🟡 中不扣分、标记面试核验；🟢 低 0）
- **封顶规则**：门槛 ② 为 **B 档 → 总分封顶 85**；A 档不封顶。**总分上限 100**（溢出按 100 计），下限 0

> 分数区间含义（便于横向对比）：**86–100 = A 档工具级实证 + 多项强加分**；**61–85 = B 档，或 A 档但加分有限（实测多数 A 档在此区间）**；**≤60 = 边缘不推**。**唯一的硬错误是「B 档算出 > 85」**（忘了封顶）；「B 档分数高于个别 A 档」是正常现象，不构成回查理由——真要查的是每笔加分贴不贴得出原句。

## 面试现场提问对照（供面试官参考）

筛进面后，下面七题用于核验。原则：第 1–4 题对应硬性要求（专业工具、SDD/TDD、AI 占比、纠错能力），**任一答崩 → 简历所写存疑，按灌水处理**；第 5–7 题为加分核验（第 5 题对简历写了 Agent 经历者必问，答崩则该项加分作废并疑灌水）。

1. **核心工具与生产落地**（门槛 ①）：常用哪款 AI 编程工具？AI 生成的代码有直接上线生产吗？
   - 合格：说得出专业工具（Cursor/Claude Code/Codex/Copilot），明确「有 / 经常上线」。
   - 淘汰：只提网页聊天工具；或「Bug 多、只敢本地测、不敢上线」。
2. **SDD/TDD 工程化**（门槛 ②）：有没有用 AI 结合 SDD/TDD 的实战？用过什么工具，流程怎么走？
   - 合格：能说出 OpenSpec / Superpowers / spec-kit 等工具或「先规格 / 测试后代码」的完整流程，并对应到真实项目。
   - 淘汰：听不懂 SDD/TDD，或说不出任何工具与流程——简历相关描述按灌水处理。
3. **AI 生成代码比例**（门槛 ① 强度）：AI 代码占比多少？还大量纯手写吗？
   - 合格：70%+，「不手写机械代码，自己理逻辑写需求，剩下交给 AI」。
   - 淘汰：10%–30%，或觉得 AI 写的不能用、还是习惯手写。
4. **对 AI 报错 / 幻觉的处理**：让 AI 改 Bug 连续 3 次都错，怎么办？
   - 合格：重写 Prompt、缩小范围喂精准上下文和日志、检查前置规格是否写错。
   - 淘汰：「那就不管 AI 了，自己手写排查」。
5. **Agent 应用落地复述**（优先方向 ① · 加分核验，简历写了 Agent 经历者必问）：讲一个你落地的 Agent 应用——业务场景、编排框架、工具调用 / MCP、上下文与记忆怎么管、上线后踩过什么坑？
   - 加分成立：细节能自然展开，有真实业务场景、线上问题与解决过程。
   - 加分作废：只会「调了下 API」「用 Dify 拖了个流程」，说不出业务效果与线上问题——判为 Demo 级；若简历重点渲染 Agent 经历，按灌水处理。
6. **AI 全栈提效**（加分）：AI 辅助下能独立完成前端到什么程度？
   - 加分：「前端页面、前后端对接都能独立搞定，一个人全量交付全栈」。
   - 偏弱：「我纯后端，AI 生成的前端样式问题多，得专业前端改，我做不了」。
7. **前沿工具敏锐度**（加分）：除了 Cursor，最近关注 / 试过哪些新 AI 编程工具？
   - 加分：如数家珍（Claude Code、v0、Bolt.new 等），有强好奇心。
   - 偏弱：半天说不上来，或只知道老牌 GitHub Copilot。
