# 分片、归并与跨仓分发

## 归并(自底向上合成——根是残差,不是基线)

根 CLAUDE.md 每会话必载是永久成本,子目录文件按需加载。所以每条信息应住在「能覆盖其全部使用点的最深节点」。要算出这个,必须先知道每个模块有什么——**先写模块再归并出根**,产出"根只剩指针和全局地雷";反过来先写根再让模块做减法,产出的是"根很肥、模块是补丁"。

1. **对齐**:按输出契约的 type+content 相似度对齐各模块候选(这就是 Phase 2 强制 JSON 契约的原因)。
2. **冲突事实**(同一维度不同取值,如模块 A 用 2 空格、B 用 4 空格):各留本地,根文件标注「存在分歧」,不强行统一——分歧本身就是要告诉 Claude 的事实。
3. **上提判定**:出现于多数模块 **且** 通过 /init 测试(「删掉这条 Claude 会犯错吗?」)。能从代码轻易发现的事实(如"用了 Lombok")即使全模块共有也不写。

## 三层分发(多仓并排工作区)

问题根源:CLAUDE.md 向上加载不认 git 边界,工作区根文件对你生效;但队友 clone 的是单个仓,根文件在他们的世界里不存在。共性内容先切一刀:

- **A 类:团队代码事实**(跨仓约定、共享接口影响面、统一部署)→ 队友必须看见 → 标记块分发
- **B 类:个人 harness 规则**(导航铁律、工具配置)→ 对没装这些工具的队友是噪音 → 只留工作区根

| 层 | 位置 | 分发 |
|---|---|---|
| 模块特有 | 各仓 CLAUDE.md 手写区 | git,团队 |
| A 类共性 | 工作区根 `shared-conventions.md`(master)→ 渲染进各仓标记块 | git,团队 |
| B 类 + 工作区粘合(map 等) | 工作区根 CLAUDE.md | 不分发,仅本机 |

单 git 仓 monorepo 退化为两层(根在仓内,A/B 合并),无需标记块。

## 标记块格式

```
<!-- shared-conventions v<N> hash:<sha256前8位> source:<工作区根>/shared-conventions.md -->
(渲染内容。勿手改;改动请编辑 master 后运行 /init-scale sync)
<!-- /shared-conventions -->
```

心智模型 = lockfile:源头唯一(master),拷贝是构建产物,用户是 DRI(单点维护),队友零工具依赖(看到的就是普通文本)。团队普遍用上 Claude Code 后可平滑升级为 private marketplace plugin,内容直接迁移。

## sync 子流程(`/init-scale sync` 直达)

1. 重算 master hash
2. 逐仓比对标记块 hash
3. 一致 → 跳过;落后于 master 的已知版本 → 直接更新;**与任何已知版本都不符 = 被手改** → 呈现 diff 让用户裁决:收编进 master 或回退。不静默覆盖——手改内容可能是队友的正确修正。
4. 同步后提醒:各仓需要 commit。

## 清算旧根(/init 产出的原根文件)

逐行三判,diff 提案确认后执行:真全局 → 保留;某模块特有 → 下沉;可被代码发现/通用废话 → 删除。

## codebase map(条件执行:目录名不自解释时才建)

map 与 CLAUDE.md 的分工是**数据 vs 指令**:map 管"什么在哪",CLAUDE.md 管"怎么做"。目录名已自解释(src/controllers 这类)时 map 是纯负债,跳过并说明。

内容两半:**结构事实**(模块依赖关系——从 codegraph import 边或 manifest 依赖机械推导,永不腐化)+ **意图语义**(每目录一句"干什么的"——人工确认,小且稳定)。

引用方式看大小:≤10 行可在根 CLAUDE.md 用 `@` 引用;更大**只留纯文本指针**(「目录职责速查:.claude/codebase-map.md」)——`@` 是会话启动时直接内联,大 map 用 `@` 等于把它塞回常驻上下文,白拆了。
