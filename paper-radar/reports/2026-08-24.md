## 本周只读一篇

**UpgradeBench: A Decision-Centric Benchmark for Upgrading Fine-Tuned LLM Specialists** · 阿里巴巴 + 长江商学院 · [arXiv 2608.20918](https://arxiv.org/abs/2608.20918) · 【全文】

**为什么是它**：它把一个每个自建微调团队每季度都要做、但从来没人量过价的决策——底座模型出新版本了，**冻结 / 移植 adapter / 用旧专家当 teacher 刷新 / 全量重训**——变成了可测量的东西，并且量出来的结果直接顶翻了本雷达自己账本里的一条判断（见文末 J8）。

沿着 Qwen 7–8B 的**完整真实发布序列**（Qwen1.5-7B-Chat 2024-02 → Qwen2-7B 2024-06 → Qwen2.5-7B 2024-09 → Qwen3-8B 2025-04，跨 14 个月）测九次升级跳，六个任务分三类（判别 / 结构化生成 / agentic 工具调用），两个尺度，训练侧成本（GPU 分钟、能耗）作为一等输出。

三个常识没活下来：

1. **「微调很快就过时」是分任务的，不是普遍规律**。意图分类上冻结旧专家跨九跳保留 99–101% 的可得收益；四代过去重训基线只动了 0.2 分，而 zero-shot 涨了 21 分——底座变强完全没吃掉这个专业化护城河，耐久性 >14 个月。但 text-to-SQL 上冻结专家**单跳就丢掉最多 59%** 的可得收益，三代内优势归零，H50 短于一个发布间隔。作者给出的组织变量是**任务能力是「底座绑定」（SQL 推理）还是「数据绑定」（标签体系、调用格式）**，这条线跟评测界惯用的判别/生成表面区分是横切的。
2. **裸抄 adapter 的成败由权重连续性决定，不由架构形状决定**。两个架构完全相同、但来自独立预训练 run 的 checkpoint 之间，把 adapter 贴过去让 Banking77 从 92.8% 崩到 42.9%——**比不挂 adapter 的 60.7% 还低**。而贴到同一份权重的继续预训练后代上，保留到重训参考水平。OLMo 那一波（训练关系有公开文档，不靠 release notes 猜）做了距离消融并**在跑之前预注册**：46B token 继续预训练时保留 0.88–0.99，2.9T token 时掉到地板，退火和 model soup 不额外造成损伤。**可移植性是距离预算，不是家族属性。**
3. **权重空间的迁移方法在这条真实血脉上，三跳里有两跳根本没定义**（hidden width / 层数 / 注意力几何都变了）。只评 shape-compatible pair 的迁移论文，描述的是这个企业实际升级中三分之二从未进入的状态。

可直接抄的一条：预先指定的决策策略在 33 个实测升级 episode 上重放（决策门与打分用测试集不相交的两半），**平均质量后悔 0.37pp、零行为回退，只花「永远重训」三分之一的算力与标注预算**；一个便宜的表征探针（256 个 prompt 上算 CKA）就能给可移植性排序（8 对上 Spearman 0.74）。

**全文验证检查单**：

1. **预印本时间线**——v1，08-21 投稿，无换壳迹象。作者自述早期草稿把 crossover 叫「half-life」，现已拆成 H50 / H0 两个指标（两者在某些任务上差一个数量级），属正常修订不是改名重投。
2. **数据采集窗口 vs 发表日期**——**这是最该注意的一条**。血脉终点是 **Qwen3-8B（2025-04）**，论文 2026-08 发表，**中间隔了约 16 个月**。Qwen3.5（2026-02 发布，本报告另一篇 TreeWY 正在用）**不在血脉里**。所以「半衰期 2–3 代」「意图分类耐久 >14 个月」这些日历数字描述的是一个**在发表前一年多就结束的时代**。按发表日期估这些数字的新鲜度会错一档——正是 J10 那个坑。可外推的是「任务是底座绑定还是数据绑定」这个结构性论点，不是月数。
3. **代码仓库状态**——论文声明释出 per-example 预测、成本日志、split manifest 与评测 harness，但**正文里没给仓库 URL，检索也没找到**。这是它最大的短板：一个以「我们释出了所有产物」为卖点的 benchmark，产物暂时无法核验。
4. **基线公平性**——这一项做得罕见地扎实。固定 PEFT 配方（QLoRA），cheap-adoption 基线与微调用同一批 checkpoint 保持底座恒定，配对 bootstrap CI，OLMo 那一波的三条预测**在跑之前预注册**，决策门与打分落在测试集不相交的两半。而且作者主动处理了分母不稳的问题：归一化保留率 R 只在参考收益 O−F 的置信下界超过 2pp 时才展示，否则标为分母不稳。
5. **硬件/版本适用边界**——**整个研究（98 次训练、193 个评测格）跑在一张 RTX 4090 上**。这既是边界也是优点：便宜到能复现，但也意味着**只覆盖 QLoRA，不覆盖全参微调**，尺度限 7–8B 与 1.5–1.8B，家族限 Qwen + OLMo，不涉 MoE。另有一条要打折看的：C4「权重资产的交付优势约为 prompt 资产的 80×」来自**附录 pilot，只测了一个 task/hop**，证据强度远低于正文主体。

**谁该读**：所有维护微调专家 / adapter 舰队的人（这是本篇的正面读者）；以及所有此刻信奉「先把 harness 做到见顶再动权重」的人——第 1 条和 C4 都在挑战这个排序，读完再决定要不要改。

## 模型

**TreeWY: Speculative Verification for Gated DeltaNet Hybrids** · Thomson Reuters（单作者） · 08-21 · [arXiv 2608.20961](https://arxiv.org/abs/2608.20961) · 【全文】

混合线性注意力模型（大部分层是 GDN，靠一个固定大小的循环状态而非增长的 KV cache）省内存，但**把投机解码打残了**：验证 k 个 draft token 时，GDN 层的循环状态在一次并行前向里会一路推到末尾，而循环状态是整个前缀的有损摘要——不能像 KV cache 那样挪个指针就回滚。现行做法（vLLM / SGLang 默认的 full-state snapshotting）是每个 draft 位置存一份完整状态快照，且**快照无法在 draft 树的分支间共享**，宽树直接内存上不可行。本文把门控 delta 规则改写成树结构 WY 变换，整棵 draft 树用**一次三角求解**算完所有节点输出，commit 时只重建那一个被接受的状态，存一个小的伪值矩阵代替逐节点状态（每头小 128×）。

关键数字：peak KV 占用低 2–3×，同等负载下抢占从 2531 次降到 1365 次；接受长度与基线基本相同（175 个配对点上平均 |Δ|=0.039）。

**全文验证**：**收益完全是条件性的**——TreeWY 只在**内存吃紧时**赢（gmu 0.6、并发 128–256：吞吐最高 1.49×、p99 TTFT 约 40× 低）；内存不紧时吞吐 0.97–0.99×（**略输**），gmu 0.9 下那个拐点根本不出现。低并发（1–64）全线 b=1.00，吞吐 0.93–1.02。**代码是 vLLM main 分支的 fork，明说「尚未上游」，且没给仓库链接**——EcoServe / FlashPrefill V2 同一形态，生产采用即长期背 rebase。基线选得公平（对的是 vLLM 生产默认 storeall，另在附录 D 上同一 sweep 对了 ReplaySSM），正确性两路校验（fp64 ~1e-15、fp32 ~1e-7）；但**最接近的并发工作 Bole（[arXiv 2608.01651](https://arxiv.org/abs/2608.01651)，SGLang 侧）没有做 head-to-head**，作者自陈是因为 Bole 没放代码——这条作者自己点破了，态度诚实但空白仍在。边界：**B200（178 GiB HBM）**，Qwen3.5-35B-A3B（TP1）与 397B-A17B（TP8），贪心起草与验证，**prefix caching 全程关闭**，深度 3 的 MTP 链。树是「已启用且正确」，**不是提速**（作者明说）。

**谁该读**：自建推理、准备上 GDN/KDA 类混合模型并想开投机解码的人。读法是先量自己的 HBM 压力——不吃紧就别折腾，这篇对你是负收益。

**Jacobian-guided Noise Injection for Quantization Robustness in Large Language Models** · Amazon · 08-21 · [arXiv 2608.20988](https://arxiv.org/abs/2608.20988) · 【仅摘要】

把 LLM 量化的稳定性瓶颈明确指到 **softmax 算子**上：它对离群值敏感、Jacobian 又依赖状态。作者先在理论上证明压住这个 Jacobian 的范数能给量化引致的性能退化定界，再据此往 **pre-attention logits** 里注入零均值高斯噪声，**方差直接由 Jacobian 的 Frobenius 范数导出**——相比拍脑袋定噪声或直接惩罚 Jacobian 的做法，它给出了「最优噪声方差」的确定方式。低比特下 WikiText 相对困惑度改善最多 40%，SigLIP 在 ImageNet-1K 上 Top-1 相对增益最多 +37%。

值得连读的地方：这跟 J9 是同一个机制从两端撞上来——FlashAttention-4 / Attn-QAT 说 Blackwell 上 attention 已经变成 softmax/SMEM-bound，这篇说量化的稳定性瓶颈也在 softmax。**同一个算子同时是性能墙和精度墙。**

**谁该读**：做低比特部署、尤其在 W4A4/FP4 上撞过精度墙的人。注意这是**训练期**策略（要动训练流程），不是 PTQ 插件，落地成本跟 FOCUS 那类不在一个量级。

## 软件系统

**RAG Deserves an Index: Why Ingest-Time Compilation Beats Query-Time Interpretation** · Endgame Labs + 武藏野大学 · 08-21 · [arXiv 2608.20845](https://arxiv.org/abs/2608.20845) · 【全文】

论点很硬：几乎每个生产 RAG 都在每次查询时让模型重新推导同一批原文的含义（消解指代、归属论断、重建结构），然后把这份工作扔掉——**这是语义层的全表扫描**，而数据库五十年前就给出了解法：把贵的活挪到写入时，做成可维护的派生结构。作者叫它 **ingest-time semantic compilation（ISC）**，两层：增量维护的 embedding（几何层）+ 编译期就做过溯源校验的原子 claim（符号层）。关键区分是**编译的是 payload 不是指针**——阅读模型直接消费带证据跨度和归属的 claim，而不是拿到一个指回原文的 1000 token 窗口。参考实现就是普通 PostgreSQL：claim 是 `facts` 表的一行，溯源不是注释而是**外键**，校验门放在抽取与插入之间，引文在原文里定位不到的候选直接丢弃（20 文档重放中拒掉 1.1%，29 条里 28 条是「模型引用的其实是转述」）。

**全文验证**：数字要拆开读。对**分块基线**（定宽/轮次感知/语义三种）它 32 个「预算×模型」格全胜，2048 token 预算下 2.2k 阅读 token 拿 85.2%，而 sweep 里最好的分块配置要 16.3k 才 72.5%——Holm 校正后 24 个对比全部存活。但对**最强基线**（LLM 上下文化分块 + 混合检索 RRF + cross-encoder 重排，且事先预注册）**是统计打平**：88.0% vs 85.2%，McNemar p=0.202；16384 预算下 87.4% vs 83.6%，p=0.076。而且**方向在开发集与留出集之间翻了个**（开发集上 facts 领先 92:88），作者主动报告了对自己不利的那一半。**所以真正的结论是成本不是精度：打平是用约 21× 的查询路径 token 买来的（47.7k vs 2.2k），且每次查询都要再付一遍。** 编译一次全语料约 26.3M token / 约 $32，等价于该语料约 580–600 次查询的额外开销——千次读内回本。

要打折的三处：① 维护那条「增量比重建便宜 33.7×」的证据是**合成 pilot**，作者自陈增量更新是理想化的、属最好情况上界；② **抽取与评判都用 Kimi K2.6**，同一模型跨管线两层——正是 Measurement Without Validity 警告的相关失效情形（作者说人工校准与换模型重判在做，未落地）；③ 「完整协议与结果」放在一份 **companion report** 里，本文没有承载它。另外语料只有一种：广播访谈转录（对话、有说话人归属），**这恰恰是 claim 编译 + 溯源最占便宜的语料形态**，没测代码库、技术文档或高频变更语料。

顺带一个独立佐证：分块侧的**阅读准确率随预算增大从 81% 降到 73%**，而 fact payload 的证据覆盖率稳在 98–99% 不随预算变——「给更多原文即使包含答案也不免费」这件事又被量了一次。

**谁该读**：做 RAG 且语料相对稳定、读多写少的人（论文自己给的判据是 break-even 读次数 R*，把它当优化器统计量而不是架构信仰）。语料变更频繁或形态与对话转录差很远的，先别照抄结论。

**Don't Solve, Just Compare: Tiny Advisors for Runtime Intervention in LLM Agents (COTA)** · 新加坡国立 · 08-21 · [arXiv 2608.21027](https://arxiv.org/abs/2608.21027) · 【仅摘要】

问题提得准：运行时干预要有用，光会**检测失败**不够，还得给出**恢复方向**；但现有做法要么交给更强的 expert solver，要么用一个能生成纠正意见的 critic——两条路都要求干预侧**再具备一次任务求解能力**，跟 actor 冗余，于是干预组件贵得下不来。COTA 的解法是把干预从「生成纠正」降格成「**只做比较**」：一个 tiny comparator 判断采样出的备选是否比 actor 的提案带来更好的后续，反复比较决定要不要干预；训练信号来自**同前缀反事实分支**构造的成对监督；被选中的备选作为**非绑定建议**返回，重规划仍由原 actor 做。WebShop / ALFWorld / τ³-Retail 三个环境 × 三个 actor 的九个设置**全部改善**，且优于所选基线。

作者点出的结论才是重点：**辅助模型的任务求解能力显著弱于 actor 时，建设性的运行时干预依然有效**——因为「比较」比「求解」便宜得多。

**谁该读**：给 agent 加验证门 / 干预层的人。跟 J6「验证者必须独立于生成者」是同一族但更进一步：验证者不但要独立，**还可以远弱于生成者**，只要把它的任务限定成比较而不是生成。注意都是学术环境（WebShop/ALFWorld/τ³），没有生产轨迹。

**Structure for Reading, Prose for Writing: Asymmetric Structural Conditioning in Multi-Agent Document Authoring** · ML Research Labs（Trellis Data） · 08-21 · [arXiv 2608.20786](https://arxiv.org/abs/2608.20786) · 【仅摘要】

一个**已部署**的投标应答系统（主权约束下跑开源权重模型），拿它跟同一家机构真实提交过的人写标书盲比。两个发现值得记：

**其一是评估方法上的**：LLM 评委在 55 个 ground-truth 章节里判系统不劣于人类 40 节、更优 4 节、无遗漏，只标出一处无依据论断。但把评委指出的每个 gap 分类后发现——**68% 是系统自己的信源里根本没有的内容**（人类作者脑子里有、管线从没拿到），所以 15 个不利判决里只有 6 个是系统本可避免的缺陷。**「与 ground truth 有差异」更多是信息可得性问题而不是写作质量问题，不区分这两者的评估会系统性低估这类系统。**

**其二是与常识相反的条件化不对称**：「把文档渲染成结构化标记而不是纯文本能改善抽取」这条已被反复验证，本文在三个阅读任务上也复现了。但**这个好处不迁移到条件化**——把标书的指令材料从散文转成嵌套 XML，配对比较下答案质量从 74% 掉到 48%。另外两条：**指名禁止某种写法会让它集中而不是消失**（96% 的残留缺陷落在 prompt 明确点名的那两种形式里）；把一个随机标注耦合到确定性窗口函数上，会让**字节完全相同的文件**抽出的需求数从 68 变成 51。

一句话：**结构放在模型读的地方，散文和自检放在模型写的地方。**

**谁该读**：写 agent prompt / 上下文工程的所有人（第二组发现是可以今天就用的）；以及做 agent 评估的人（第一组发现是评估设计上的硬教训）。

**No Judgment Without a Reason: Counterfactual Receipts for Versioned AI Evaluators** · 阿里巴巴 + 长江商学院 · 08-21 · [arXiv 2608.20938](https://arxiv.org/abs/2608.20938) · 【仅摘要】

（与 UpgradeBench 同一组作者，同日两篇。）

问题：**评委可以保住正确标签，却是因为错误的理由才改的判断**。当评委输出在门控 agent 动作、路由人工复核、或作为反馈回流进训练时，这件事就要命，而大多数评估协议只记最终标签对不对。作者把评委状态拆成三类有类型的来源——grounds（证据）、norms（决策规则）、authority（规则适用性）——替换任意子集得到八格反事实表（judgment cube），**judgment receipt** 就是能复现修订后裁决的、包含极小的来源替换族。关键区分：**执行过的反事实才能认证一张 receipt，语言模型只能预测一张。**

ReasonBench：845 个独立切分的来源单元产出 19,520 个 case 加 7,200 个配对对照，五个种子的研究在开任何结果之前用 content hash 冻结。Qwen3-1.7B 直接预测 receipt 拿到 **98.41%** 精确 receipt 准确率；预测完整 cube 反而 96.99%，配对差 −1.42pp（[−2.87,−0.30]）——**冻结前登记的「cube 监督会改善 receipt 预测」这一假设被拒**，Qwen3-0.6B 三种子复现一致（−1.26pp）。

但作者说「更重要的发现是高准确率掩盖了什么」：**对来源顺序做保义置换后，同一张 receipt 只有 54.8%（直接预测）/ 49.2%（cube 预测）能被复现**。98.41% 与 54.8% 之间的落差就是本篇的真正产出。

**谁该读**：所有把 LLM-as-judge 接进 CI / 门控 / 数据回流的人。可直接照抄的两件事：把评委的**版本迁移**当成需要认证的对象、以及**上保义置换测试**——一个测下来能把 98% 打回 55% 的探针，成本极低。

## 落选池

- **Is Multimodal Speculative Decoding Ready for Diffusion-Based Parallel Drafting?** · 中国联通 + 南大 · [arXiv 2608.20743](https://arxiv.org/abs/2608.20743) —— 综述 + 跨架构实证。结论是「块并行/扩散式起草在多模态上基本没被探索」。摘要里的 3.6× 是 DFlash/DSpark 在**纯文本**日常对话上的数字，不是多模态结果，别误读。
- **Asymmetric Capacity Allocation in Self-Refinement Pipelines** · UCI + Drexel · [arXiv 2608.21345](https://arxiv.org/abs/2608.21345) —— 首个按阶段（生成/批判/修订）系统考察模型尺寸的工作，指出把模型尺寸当实现细节会浪费资源。方向对，数字待核。
- **Beyond Endpoint Gains: A Weight-Delta Audit of Medical Specialization** · IIT Kanpur + Oracle Health AI + MBZUAI · [arXiv 2608.20768](https://arxiv.org/abs/2608.20768) —— 不看端点分差而审计「释出的权重更新本身」，两对公开的通用→医疗专家 checkpoint。与 UpgradeBench 是同一问题的另一侧切法。
- **When Trust Meets Truth: Trust–Truth Separability in LLM-as-Judge** · NII + 阿姆斯特丹大学等 · [arXiv 2608.21097](https://arxiv.org/abs/2608.21097) —— LLM 评委的多维评估里「可信」与「为真」能不能分开。与 No Judgment 一篇同线，规模较小。
- **Knowing but Not Saying: Preventing Factual Access Failures in LLM SFT via Recall-Anchored Distillation** · [arXiv 2608.20794](https://arxiv.org/abs/2608.20794) —— 把 SFT 的域外事实退化从「灾难性遗忘」细化成 **factual access failure**：开放式事实回答失败不等于底层事实被抹掉。若成立，会改写账本里 SFT-遗忘那条的机制描述。

## 判断账本动态

**J8【存疑】** —— 「微调对模型升级脆弱是结构性规律；先把 harness/prompt 空间做到见顶，再考虑动权重」被 UpgradeBench 从两个方向挑战：

- **脆弱性不是普遍规律，是分任务的**。九次真实升级跳上，意图分类（数据绑定）冻结保留 99–101%、耐久 >14 个月；text-to-SQL（底座绑定）单跳丢 59%、三代归零。J8 原文把它当无差别的结构性规律，过强了。正确的形式应该是「**底座绑定的能力对升级脆弱，数据绑定的能力不脆弱**」。
- **「harness 先行」这个排序也被顶了一下**：C4 报告权重资产的交付优势约为 prompt 资产的 80×，且**不比 prompt 资产更脆弱**，而 prompt 资产的最优选择反倒**跨代翻转**。
- **但存疑不等于推翻**：C4 是附录 pilot，只测了一个 task/hop，证据强度低；且 UpgradeBench 血脉止于 Qwen3-8B（2025-04），比发表日期早 16 个月，日历数字不可外推。J8 的另一半支撑（MAP/CAP 的 70% 不微调，理由是升级脆弱 + 维护成本）也没有被直接反驳——维护成本那条本篇没测。

**J1 印证** —— TreeWY 是又一个「加速比只在特定 regime 存在」的实例，且形态是新的：不是并发分布也不是卡型，而是 **HBM 预算**。同一份 kernel 在 gmu 0.6 / 并发 256 下吞吐 1.49×、p99 TTFT 约 40× 低，在 gmu 0.9 下拐点根本不出现、吞吐 0.97–0.99×（略输）。已追加进 J1 支撑。

**J7 印证并扩展** —— RAG Deserves an Index 把「系统级决策压过算法选择」推到一个新轴：**把语义工作挪到 ingest 时**。同时它独立复现了 context 不是精度中性的（分块阅读准确率随预算 81%→73%，而编译 payload 的证据覆盖稳在 98–99%）。**扩展时保留了它的真实强度**：对最强基线是统计打平（p=0.202）且方向在开发/留出集之间翻转，真正买到的是 21× 的查询路径 token，不是精度。

**J13 印证** —— 两个新来源：① No Judgment Without a Reason——98.41% 的 receipt 准确率在保义置换下只剩 54.8%，是「高分掩盖非稳健」的干净实例，且它的**预注册假设被自己的数据拒绝**；② RAG Deserves an Index 的抽取与评判**共用 Kimi K2.6**，正是 Measurement Without Validity 说的同族模型跨层导致上界更紧的情形（作者已披露并在补人工校准）。已追加。

**新增判断候选（暂不入账）** —— 「微调资产的可移植性由**权重连续性**决定，不由架构形状决定；可移植性是距离预算不是家族属性」。证据很强（Qwen + OLMo 两个家族、OLMo 侧还是预注册的距离消融），但目前**只有 UpgradeBench 一个独立来源**，OLMo 那一波是同篇内部验证不算第二来源。按账本规则不收，等第二个独立来源出现再立条。
