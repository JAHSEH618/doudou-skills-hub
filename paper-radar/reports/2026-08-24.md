# 微调资产的保质期，由任务决定

底座升级之后，旧专家模型是否还值得保留？UpgradeBench 给出的答案随任务变化很大。意图分类中的旧专家保留了大部分专业化收益，text-to-SQL 却迅速失去优势；同形状的 adapter 也可能在换底座后低于新底座自身的表现。

这期几篇论文都在讨论何时值得付出迁移成本。TreeWY 的收益集中在循环状态快照挤占显存的时候，RAG Deserves an Index 则把查询时反复支付的解释成本移到入库阶段。读它们时，需要同时记下效果、前置投入和负载变化，单看最高分或最高倍率不够。

## 底座升级，先看旧专家还保留多少价值

微调、移植和重训是不同成本的选择。UpgradeBench 将它们放进真实模型发布序列，LoRA 的参数研究则帮助理解一份 adapter 当初是怎样训练出来的。

### UpgradeBench：任务决定专家模型的耐久性

UpgradeBench: A Decision-Centric Benchmark for Upgrading Fine-Tuned LLM Specialists · 阿里巴巴 + 长江商学院 · [arXiv 2608.20918](https://arxiv.org/abs/2608.20918)

底座模型发布新版本后，维护者可以冻结旧专家、移植 adapter、用旧专家蒸馏刷新，或重新训练。UpgradeBench 比较这几种选择的质量与成本，结果不支持把“微调很快过时”当作所有任务的共同规律。

沿着 Qwen 7–8B 的完整真实发布序列（Qwen1.5-7B-Chat 2024-02 → Qwen2-7B 2024-06 → Qwen2.5-7B 2024-09 → Qwen3-8B 2025-04，跨 14 个月）测九次升级跳，六个任务分三类（判别 / 结构化生成 / agentic 工具调用），两个尺度，训练侧成本（GPU 分钟、能耗）作为一等输出。

实验分别比较了任务耐久性、adapter 迁移和真实升级路径。

1. 「微调很快就过时」是分任务的，不是普遍规律。意图分类上冻结旧专家跨九跳保留 99–101% 的可得收益；四代过去重训基线只动了 0.2 分，而 zero-shot 涨了 21 分——底座变强完全没吃掉这个专业化护城河，耐久性 >14 个月。但 text-to-SQL 上冻结专家**单跳就丢掉最多 59%** 的可得收益，三代内优势归零，H50 短于一个发布间隔。作者给出的组织变量是任务能力是「底座绑定」（SQL 推理）还是「数据绑定」（标签体系、调用格式），这条线跟评测界惯用的判别/生成表面区分是横切的。
2. 裸抄 adapter 的成败由权重连续性决定，不由架构形状决定。两个架构完全相同、但来自独立预训练 run 的 checkpoint 之间，把 adapter 贴过去让 Banking77 从 92.8% 崩到 42.9%——**比不挂 adapter 的 60.7% 还低**。而贴到同一份权重的继续预训练后代上，保留到重训参考水平。OLMo 那一波（训练关系有公开文档，不靠 release notes 猜）做了距离消融并在跑之前预注册：46B token 继续预训练时保留 0.88–0.99，2.9T token 时掉到地板，退火和 model soup 不额外造成损伤。可移植性是距离预算，不是家族属性。
3. 权重空间的迁移方法在这条真实血脉上，三跳里有两跳根本没定义（hidden width / 层数 / 注意力几何都变了）。只评 shape-compatible pair 的迁移论文，描述的是这个企业实际升级中三分之二从未进入的状态。

决策策略的重放结果是：预先指定的决策策略在 33 个实测升级 episode 上重放（决策门与打分用测试集不相交的两半），**平均质量后悔 0.37pp、零行为回退，只花「永远重训」三分之一的算力与标注预算**；一个便宜的表征探针（256 个 prompt 上算 CKA）就能给可移植性排序（8 对上 Spearman 0.74）。


这组升级序列止于 2025 年 4 月的 Qwen3-8B，距离论文发表约 16 个月。耐久月数描述的是那一段发布历史。研究使用一张 RTX 4090 完成 98 次训练和 193 个评测格，覆盖 QLoRA、小规模 Qwen 与 OLMo，不覆盖全参微调或 MoE；作者承诺的复现材料当时还没有可核对的仓库地址。

### LoRA 的训练效果与迁移能力是两组问题

Thinking Machines Lab / John Schulman · 2025-09-29 · [博客原文](https://thinkingmachines.ai/blog/lora/)

作者比较 LoRA 与全参微调时，把容量、训练数据量、batch size 和施加层分开扫描。在文中的小到中等规模后训练数据上，调好配置的 LoRA 可以接近全参结果；数据超过容量后，差距又会出现。只在 attention 层挂 adapter 的结果，也不能替代覆盖 MLP 的配置。

这篇博客提供了理解本期微调论文的参数背景。它考察的是给定底座上的训练效果；底座升级后 adapter 能否迁移，需要 UpgradeBench 那样的另一组实验。作者的学习率关系也只适合作为扫描起点，不能从一个配方推出跨任务的统一最优值。

## 状态与精度，会改变优化的回报

循环状态快照占用显存时，投机解码需要另外一套状态管理；低精度训练则要处理 softmax 对扰动的敏感性。两项工作面对的资源约束不同。

### TreeWY：显存吃紧时才出现的收益

TreeWY: Speculative Verification for Gated DeltaNet Hybrids · Thomson Reuters（单作者） · 08-21 · [arXiv 2608.20961](https://arxiv.org/abs/2608.20961)

混合线性注意力模型（大部分层是 GDN，靠一个固定大小的循环状态而非增长的 KV cache）省内存，但增加了投机解码的状态管理成本：验证 k 个 draft token 时，GDN 层的循环状态在一次并行前向里会一路推到末尾，而循环状态是整个前缀的有损摘要——不能像 KV cache 那样挪个指针就回滚。现行做法（vLLM / SGLang 默认的 full-state snapshotting）是每个 draft 位置存一份完整状态快照，且快照无法在 draft 树的分支间共享，宽树直接内存上不可行。本文把门控 delta 规则改写成树结构 WY 变换，整棵 draft 树用一次三角求解算完所有节点输出，commit 时只重建那一个被接受的状态，存一个小的伪值矩阵代替逐节点状态（每头小 128×）。

关键数字：peak KV 占用低 2–3×，同等负载下抢占从 2531 次降到 1365 次；接受长度与基线基本相同（175 个配对点上平均 |Δ|=0.039）。


收益集中在显存吃紧的设置：gmu 0.6、并发 128–256 时吞吐最高 1.49×，p99 TTFT 约低 40×；gmu 0.9 时吞吐为 0.97–0.99×。实验使用 B200、Qwen3.5-35B 与 397B，关闭 prefix caching。实现尚未进入上游，接入与维护成本仍需单独估计。

### 量化误差从 softmax 的敏感性入手

Jacobian-guided Noise Injection for Quantization Robustness in Large Language Models · Amazon · 08-21 · [arXiv 2608.20988](https://arxiv.org/abs/2608.20988) · 摘要导读

把 LLM 量化的稳定性瓶颈明确指到 softmax 算子上：它对离群值敏感、Jacobian 又依赖状态。作者先在理论上证明压住这个 Jacobian 的范数能给量化引致的性能退化定界，再据此往 pre-attention logits 里注入零均值高斯噪声，方差直接由 Jacobian 的 Frobenius 范数导出——相比拍脑袋定噪声或直接惩罚 Jacobian 的做法，它给出了「最优噪声方差」的确定方式。低比特下 WikiText 相对困惑度改善最多 40%，SigLIP 在 ImageNet-1K 上 Top-1 相对增益最多 +37%。

softmax 的性能开销与量化敏感性需要分别检查。减少计算时间的实现优化，仍要经过精度测试；降低量化误差的方法，也要测量它额外引入的计算与存储成本。


## 把重复工作移到系统能复用的位置

RAG、运行时建议和文档写作都涉及一项选择：哪些分析应提前组织，哪些决定必须留给当前任务。收益取决于复用次数，也取决于信息是否完整。

### RAG 索引：用入库成本换查询成本

RAG Deserves an Index: Why Ingest-Time Compilation Beats Query-Time Interpretation · Endgame Labs + 武藏野大学 · 08-21 · [arXiv 2608.20845](https://arxiv.org/abs/2608.20845)

论文提出，几乎每个生产 RAG 都在每次查询时让模型重新推导同一批原文的含义（消解指代、归属论断、重建结构），然后把这份工作扔掉——这是语义层的全表扫描，而数据库五十年前就给出了解法：把贵的活挪到写入时，做成可维护的派生结构。作者叫它 ingest-time semantic compilation（ISC），两层：增量维护的 embedding（几何层）+ 编译期就做过溯源校验的原子 claim（符号层）。

阅读模型直接消费带证据跨度和归属的 claim，省去从 1000 token 原文窗口重新提取的步骤。参考实现在 PostgreSQL 中把 claim 存为 `facts` 表的一行，用外键关联出处。抽取后的候选在插入前接受校验，引文无法在原文定位的候选会被丢弃。20 文档重放中，1.1% 的候选被拒绝；29 条中有 28 条的问题是模型把转述作为了引用。

要打折的三处：① 维护那条「增量比重建便宜 33.7×」的证据是合成 pilot，作者自陈增量更新是理想化的、属最好情况上界；② **抽取与评判都用 Kimi K2.6**，同一模型跨管线两层——正是 Measurement Without Validity 警告的相关失效情形（作者说人工校准与换模型重判在做，未落地）；③ 「完整协议与结果」放在一份 companion report 里，本文没有承载它。另外语料只有一种：广播访谈转录（对话、有说话人归属），这恰恰是 claim 编译 + 溯源最占便宜的语料形态，没测代码库、技术文档或高频变更语料。

顺带一个独立佐证：分块侧的**阅读准确率随预算增大从 81% 降到 73%**，而 fact payload 的证据覆盖率稳在 98–99% 不随预算变——「给更多原文即使包含答案也不免费」这件事又被量了一次。


强基线改变了结论。面对上下文化分块、RRF 与 cross-encoder 重排，准确率 88.0% 对 85.2% 的差异没有统计显著性（p=0.202）；优势集中在查询 token 成本。编译语料约需 26.3M token、32 美元，约对应 580–600 次查询的额外开销。语料只有广播访谈转录，抽取与评判都用 Kimi K2.6，这些条件限制了泛化。

### 分块基线也需要完整的上下文

Anthropic · 2024-09-19 · [博客原文](https://www.anthropic.com/news/contextual-retrieval)

文章在分块进入 embedding 与 BM25 索引前，为每个块补一段由整篇文档生成的上下文，再结合检索与 reranking。它处理的是块离开原文后缺少公司名、时间或主题归属的问题。原文给出生成提示、预处理流程和不同检索组合，适合作为 RAG 对照实现的阅读入口。

这也解释了本期 RAG 论文为什么需要一个足够强的基线：单纯固定分块与经过上下文化、混合检索、重排的系统，成本和效果并不相同。博客报告的检索失败率针对自身数据与 recall 口径，不能替代回答质量，更不能直接与论文的准确率相减。

### 小模型顾问只比较候选，不替执行者重写计划

Don't Solve, Just Compare: Tiny Advisors for Runtime Intervention in LLM Agents (COTA) · 新加坡国立 · 08-21 · [arXiv 2608.21027](https://arxiv.org/abs/2608.21027) · 摘要导读

问题提得准：运行时干预要有用，光会检测失败不够，还得给出恢复方向；但现有做法要么交给更强的 expert solver，要么用一个能生成纠正意见的 critic——两条路都要求干预侧再具备一次任务求解能力，跟 actor 冗余，于是干预组件贵得下不来。COTA 的解法是把干预从「生成纠正」降格成「只做比较」：一个 tiny comparator 判断采样出的备选是否比 actor 的提案带来更好的后续，反复比较决定要不要干预；训练信号来自同前缀反事实分支构造的成对监督；被选中的备选作为非绑定建议返回，重规划仍由原 actor 做。WebShop / ALFWorld / τ³-Retail 三个环境 × 三个 actor 的九个设置全部改善，且优于所选基线。

这组实验显示，辅助模型的任务求解能力显著弱于 actor 时，建设性的运行时干预依然有效。比较器只需判断候选的相对收益，降低了对辅助模型独立求解能力的要求。


### 读需求与写文章需要不同的组织方式

Structure for Reading, Prose for Writing: Asymmetric Structural Conditioning in Multi-Agent Document Authoring · ML Research Labs（Trellis Data） · 08-21 · [arXiv 2608.20786](https://arxiv.org/abs/2608.20786) · 摘要导读

一个已部署的投标应答系统（主权约束下跑开源权重模型），拿它跟同一家机构真实提交过的人写标书盲比。实验分别检查了评委的判断依据和输入材料的组织方式。

其一是评估方法上的：LLM 评委在 55 个 ground-truth 章节里判系统不劣于人类 40 节、更优 4 节、无遗漏，只标出一处无依据论断。但把评委指出的每个 gap 分类后发现——**68% 是系统自己的信源里根本没有的内容**（人类作者脑子里有、管线从没拿到），所以 15 个不利判决里只有 6 个是系统本可避免的缺陷。「与 ground truth 有差异」更多是信息可得性问题而不是写作质量问题，不区分这两者的评估会系统性低估这类系统。

其二是与常识相反的条件化不对称：「把文档渲染成结构化标记而不是纯文本能改善抽取」这条已被反复验证，本文在三个阅读任务上也复现了。但这个好处不迁移到条件化——把标书的指令材料从散文转成嵌套 XML，配对比较下答案质量从 74% 掉到 48%。另外两条：指名禁止某种写法会让它集中而不是消失（96% 的残留缺陷落在 prompt 明确点名的那两种形式里）；把一个随机标注耦合到确定性窗口函数上，会让字节完全相同的文件抽出的需求数从 68 变成 51。

这组结果支持分别测试阅读输入与写作输入的组织方式。结构化在抽取任务上的收益，不能直接外推到生成任务。


## 评分变化，需要能回到原始理由

模型与系统都会迭代，评价规则也会变。留下评分依据可以帮助区分规则变化与结果变化。

### 给评委留下可检查的理由

No Judgment Without a Reason: Counterfactual Receipts for Versioned AI Evaluators · 阿里巴巴 + 长江商学院 · 08-21 · [arXiv 2608.20938](https://arxiv.org/abs/2608.20938) · 摘要导读

（与 UpgradeBench 同一组作者，同日两篇。）

评委可能保持正确标签，却依据错误理由改变判断。当评委输出在门控 agent 动作、路由人工复核、或作为反馈回流进训练时，错误理由会继续影响后续决策，只记录最终标签无法识别这类问题。作者把评委状态拆成三类有类型的来源——grounds（证据）、norms（决策规则）、authority（规则适用性）——替换任意子集得到八格反事实表（judgment cube），judgment receipt 就是能复现修订后裁决的、包含极小的来源替换族。认证 receipt 需要实际执行相应的反事实对照，模型直接输出的结果仍是预测。

ReasonBench：845 个独立切分的来源单元产出 19,520 个 case 加 7,200 个配对对照，五个种子的研究在开任何结果之前用 content hash 冻结。Qwen3-1.7B 直接预测 receipt 拿到 **98.41%** 精确 receipt 准确率；预测完整 cube 反而 96.99%，配对差 −1.42pp（[−2.87,−0.30]）——冻结前登记的「cube 监督会改善 receipt 预测」这一假设被拒，Qwen3-0.6B 三种子复现一致（−1.26pp）。

但作者说「更重要的发现是高准确率掩盖了什么」：**对来源顺序做保义置换后，同一张 receipt 只有 54.8%（直接预测）/ 49.2%（cube 预测）能被复现**。高预测准确率没有保证结果在保义置换下仍然稳定。


## X 上的技术讨论

### Varun Mohan：代码检索需要组合检索方法

@_mohansolo · 2025-03-12 · [X 原帖](https://x.com/_mohansolo/status/1899630246862966837)

原帖谈到代码库增大后 embedding 检索的局限，以及文件搜索、知识图谱检索与重排的组合。它提供了一个实践问题：索引规模增加时，原有检索启发式是否仍稳定。帖子观点不能替代在目标代码库上的对照测量。
