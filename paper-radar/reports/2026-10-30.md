# pass@1 的代价

10 月 29 日同一天发生了两件事。一篇理论论文把 RLVR 对模型的作用钉死了：pass@1 的提升在 population limit 下就是对策略分布的重加权，任何这样的提升都带着一个显式、可计数的 pass@k 代价。同一天，Mistral 开放了 1T 参数模型的权重，vLLM 在同一个帖子里给出了完整的服务端优化套件。本期的材料都围绕「测量够到哪里」这个问题组织：RLVR 到底改了什么，benchmark 又没显示什么；memory-bound 的 MoE 推理卡在哪，相位感知能修多少；低精度能推到哪一步，每种方法的边界在哪里。

第一节拆 RLVR 的理论部分，恒等式、无免费午餐定理、代价上界和前沿，再用两条已发表的 pass@k 曲线做验证。第二节补评估侧的两篇审计论文，一篇审数据集本身，一篇审 agent 动作的时机假设。第三节是 CPU-GPU 节点上 MoE 推理的 prefill/decode 跷跷板。第四节问低精度的边界，线性递归的七个不变量、张量核心的 FP32 仿真，外加 MoE 路由动力学和两篇摘要级短文。第五节是 Mistral Large 4 的工程全套。第六节是调度与可观测性。本期 8 篇论文（3 篇全文验证）、工程实践详条目 4 条与简条目 3 条、资讯 3 条，X 无新帖。

## 无免费午餐：RLVR 的 pass@k 代价

**【论文，全文】** [There Is No Free Lunch in RLVR: Every pass@1 Gain Has a pass@k Price](https://arxiv.org/abs/2610.39295)（arXiv 2610.39295，v1 提交于 2026-10-29，[代码](https://github.com/yliusci/no-free-lunch-rlvr) 按 CC BY 4.0 放出）。

论文要回答的问题是：RLVR 之后 pass@1 上升，但某些数据集上 pass@k 在 k 足够大时跌到基座模型之下，这个现象的机制是什么，代价能不能算。常见解释是「多样性下降」。这篇把它变成预算问题，并给出了完整的理论链。

**模型与精确恒等式（定理 1）。** 把模型看成有限策略空间 S 上的概率分布，prompt 服从分布 P，RLVR 放在 population limit（GRPO 及其变体）。以基座模型为锚的 mirror descent 产生精确恒等式 w_τ ∝ w₀·exp(τf)，即 RLVR 一阶的作用就是把每个策略的质量按平均收益重新加权。两个技术结果封掉了反例空间：GRPO 的组内基线与 top-k 奖励截断不破坏这个形式，命题 1 给出 per-prompt 随机组基线引入的总变差上界 O(δ)，作者自实现里测到的 TV 小于 3×10⁻⁴。

**定理 2（无免费午餐）。** 论文定义 exclusive specialization：每个策略是唯一正确解一道正质量 prompt 集合。在此条件下，免费午餐（严格抬高 pass@1 且 pass@k 不掉）的存在性经 Stiemke alternative 定理等价于存在一组严格正的 prompt 价格，使所有策略的加权收益相等。推论给出可检验的充分条件 dominant specialization：若策略 j 独占的 prompt 上基座成功率不低于 d，其余 prompt 上不超过 ε，且 (M−1)ε < d/2，则免费午餐不存在。两个容易误读的地方被正面处理了。唯一最优解者的存在不够，论文给了反例：多个策略同为最优时免费午餐可以存在。必要性方向同样干净：免费午餐存在当且仅当存在一个策略在所有 prompt 上支配所有其他策略。pass@k 掉落的成因于是清楚了，不在模型「学坏了」，在 prompt 空间存在互斥的解题路径。

**定理 3（代价可计数）。** 利用核的 total positivity，pass@k 交叉点（曲线跌到基座之下的次数）的数量以 per-prompt 成功率 CDF 位移的符号变化数为上界，且上界是紧的：对任意 m ≥ 0 都能构造恰好 m 个交叉点的例子。fine coverage（最难 prompt 只能被基座平均收益以下的策略解出）保证交叉出现；位移保序时收敛为单次交叉。pass@k 的下跌因此是一个可测量、有上界的量，不是模糊的「多样性变差」。

**定理 4（前沿与选择）。** 约束 max_k(base − RL) ≤ γ 下最大化 pass@1，解恰好描出 pass@1↔pass@k 的 Pareto 前沿：γ 控制你接受多大的 pass@k 跌幅，完全消灭交叉的代价是 pass@1 收益的全部。前沿上的点可以选，前沿本身不能挪。

**证据（第 5 节，无新训练）。** 作者把两条已发表的 pass@k 曲线放进诊断工具。一条是 Qwen2.5-7B 在 Omni-MATH 上的 GRPO 训练（Zhou et al.，[arXiv 2607.20543](https://arxiv.org/abs/2607.20543)，表 2，数值由作者转写）：相对基座的优势在 k=1 为 +0.149，k=16 为 +0.144，k=64 为 +0.104，k=128 为 +0.030，k=256 为 −0.008，单次交叉出现在 128 到 256 之间，正好落在保序区间。同文的 GRPO+PBA（正向偏置优势，一种多样性干预）曲线在全部测到的 k 上都压在基座之上，前沿视角给出的解释是：plain GRPO 处于前沿内部，多样性奖励把解往外推，同时买到更高的 pass@1 和更晚的交叉。MATH500 上 k≤256 无交叉。作者对证据定位的表述很克制：一个数据集、五个预算、数值转写自公开表格，是佐证，不是证明。论文同时给出可证伪条件：保序位移下出现两次统计支持的符号变化，或在已验证 specialization 假设下看到无 per-prompt 损失的 pass@1 收益，分别直接反驳对应定理。

**熵恒等式（定理 5）。** 同一个 tilt 恒等式导出熵塌缩轨迹的精确公式：介观区间内 b − R = a_κ·exp(H/κ)，κ 由 log(b−R) 对 H 的斜率定出。拟合值 2.006、0.986、0.487，预测 2、1、0.5，误差 2.6% 以内；恒等式本身验证到 2×10⁻⁶。有一组数据值得记录：实验里策略熵从 2.77 掉到 2.14，token 级熵反而从 6.85 升到 7.27。「熵塌缩」发生在策略层，混用两个层面会画出错的曲线。

**边界。** population limit 是前提，有限组瞬态的非单调性论文单独记录。exclusive 与 dominant specialization 假设没有在真实 LLM 上验证，论文给出的回答是诊断工具本身：输入基座与 RL 模型的 pass@k 两列，输出交叉点数、符号变化上界、保序检验和价格（max_k(base−RL)）。作者建议所有 RLVR 报告在 pass@1/pass@k 之外加两个数：价格与交叉点。实证部分复用两条已发表曲线，未做新实验。

**解说与联动。** 未找到第三方解说。同族前作有三篇：Yue et al. 2025（[arXiv 2511.16231](https://arxiv.org/abs/2511.16231)）最早观察到反转并解释为分布重加权；Zhou et al. 2026（[arXiv 2607.20543](https://arxiv.org/abs/2607.20543)）诊断了反转并提出 PBA；[arXiv 2609.22547](https://arxiv.org/abs/2609.22547) 是同期手稿，作者已显式划界。判断账本联动：J13（per-item 差分指标必须配冻结对照臂）由此获得机制解释，pass@k 下跌是结构性重加权而非测量伪影，冻结基座模型恰是对照物；J21（数字必须带条件集读）增加一个实例，+0.149 到 −0.008 是 k 的函数，不带 k 的「RLVR 变好了」是半句话。

## 评估看不见的东西：数据集审计与动作时机

两篇摘要级论文，共同点是不测模型，测测量本身。

**【论文，摘要级】** [Well-Specified and Well-Tested? Assessing SWE-bench-Style Datasets with a Self-Evolving Agent](https://arxiv.org/abs/2610.39417)（arXiv 2610.39417）。切入点：SWE-bench 风格数据集是编码 agent 评测的事实标准，但 task clarity 与 test coverage 直接决定一个实例是否可解、可验证。工作是用一个自演化 agent 对这些数据集本身做评估，标题就是方法名。与上一节连读的意义在于：pass@k 的价格是标准 pass@1 榜单看不见的分布变化，数据集层面的审计是「benchmark 看不见什么」的另一层。摘要级范围：评估协议、自演化循环的具体机制与数据集质量结果未读，需全文核对。

**【论文，摘要级】** [What Does "Now" Mean to Your Computer-Use Agent? Stale Screenshots, Page Loads, and Which Check to Run Before a Click](https://arxiv.org/abs/2610.39282)（arXiv 2610.39282）。computer-use agent 在截图上规划几秒再点屏，页面若在此期间变化，点击会落在非目标元素上。此前工作把规划间隔当作风险来源。这篇在 31 个公开网页上测量计划点击，结论是把风险来源挪了位置：问题主要在页面加载。摘要报告的数字是 0.4% 的点击（规划于完全加载的页面）最终落在非目标元素上，标题里的「which check to run before a click」对应给出的点击前检查方案。摘要级范围：测量口径、0.4% 的完整定义与检查方案的效果均待全文。

## memory-bound MoE 推理的跷跷板

**【论文，全文】** [PDScope: Breaking the Prefill-Decode Seesaw for Memory-Bound MoE Inference](https://arxiv.org/abs/2610.39216)（arXiv 2610.39216，v1 提交于 2026-10-29，国防科大 + 启元实验室；代码仓库为审稿用匿名占位 [github.com/nezha-Anonymous/PDScope](https://github.com/nezha-Anonymous/PDScope)）。

问题定义：本地 MoE 部署在 CPU-GPU 节点上，GPU 显存放不下全部专家，多数专家驻留 CPU 内存。prefill 是 compute-bound，希望尽量多地把专家装进 GPU；decode 是 I/O-bound，希望少花 PCIe 流量。相位无关的调度只能选一边：静态放置（kTransformers）对 decode 友好、prefill 吃亏；按需加载（Fate）反过来；逐层反应式调度（HybriMoE、MoE-APEX、Fiddler）看当前层，不看下一步。跷跷板在低 batch 下最明显，单 GPU 节点、本地助手、文档工具正是这种配置的主场。

方法三件套。PhasePer 是分相位训练的专家激活 rank 预测器，离线用 128 个 ShareGPT batch（输入 4096、输出 512 token）训练，DeepSeek-V2-Lite 与 Qwen3-30B-A3B 上 Top-6 准确率 94%；域外数据（DPO、LLaVA）掉 4.8–5.3 个百分点，始终不低于 80%；对照 Fate 的 gate 推断是 68.4%，高出 15 个百分点。AdaptSched 把当前层放置与下一层预取联合优化，预取深度按预测置信度校准，结果编译成静态计算图，运行时没有逐专家调度。执行层：zero-copy 异步 I/O（乒乓缓冲、每专家 3 条 CUDA 流、pinned memory）把 PCIe 带宽利用率做到 66–80%；图引导的 CPU 缓存预取；调度开销 8.1 ms，与专家计算重叠。

数字（A100 + 双 Xeon 6230R 与 RTX 3090 + EPYC 7452，PCIe 4.0×16，GPU 显存封顶 24 GB，10 次运行均值）：prefill（4096 token）最高 10.3× Fate、8.6× kTransformers、5.8× Fiddler、4.4× HybriMoE、2.5× MoE-APEX；decode 最高 6.1× Fate、2.9× kTransformers。新模型 DeepSeek-V4-Flash 上单 batch prefill 2.82–5.03×、decode 1.26–1.97×；batch 32 时 prefill 2.35–5.37×、decode 3.14–5.65×。一个值得记住的负向观察：batch 16→32，prefill 增益只有 5.2%（2048 token）和 0.7%（4096 token），这种配置下 batch 16 已经压满硬件，「batch 越大吞吐越高」的直觉在这里不成立。鲁棒性：PhasePer 准确率退化到 45–70% 时 prefill 吞吐只掉 6.4–11.3%，层内局部重评估可以回落到按需加载兜底。

边界：PCIe 4.0 平台，没有 NVLink 与 CXL 对照；不支持 prefill/decode overlap，作者的理由是 memory-bound 下 overlap 加剧争用；基线各自调到自报最优配置（公平性成立，预热 3 轮）；离线校准每模型在 A100 上不超过 30 分钟。

**【论文，摘要级】** [Softmax Routing Dynamics in Mixture-of-Experts Models: Collapse and Recovery](https://arxiv.org/abs/2610.39442)（arXiv 2610.39442）。与上一节的部署侧相对，这篇看训练侧的 MoE 动力学：softmax 路由把概率集中到部分专家、压制其余专家，这篇研究集中如何形成、为何持续、被压制的概率如何恢复。摘要里可见的框架：专家固定时，一个 stationary loss barrier 识别出支撑最优路由输出的面；共同目标平方损失模型里专家输出自由可训（后续机制在截断之外）。摘要级范围：collapse 的持续性条件与恢复机制未读。

## 低精度能推到哪一步

**【论文，全文】** [LinQuant: Functional Invariances for Low-Precision Linear Recurrences](https://arxiv.org/abs/2610.39418)（arXiv 2610.39418，v1 提交于 2026-10-29）。

线性注意力与 SSM 家族（Mamba-2、Jamba、Nemotron-H 混合架构）用 O(L) 状态换长上下文，低精度计算是部署的最后一公里。这篇的切入点不是 kernel 技巧，是「函数不变量」：一个量化方案之下，哪些函数保持不变，代价是什么。

方法骨架。线性递归的 chunkwise 分解产生四个矩阵乘（状态写、状态读、局部打分、chunk 内输出）加 chunk 间状态传递。论文列出 7 个函数不变量：4 个轴变换（R_QK、D_QK、R_V、D_V，即对各矩阵乘操作数的基变换）与 3 个吸收（把衰减/写入因子拆到矩阵乘的操作数里）。不变量族对 linear、gated、delta rule 各变体（Mamba-2、GLA、DeltaNet、Gated DeltaNet、KDA、线性注意力）分别给出适用性。

受控实验：「mixer zoo」覆盖上述 6 个 mixer，340M 与 1.3B 规模，15B/100B SlimPajama token，WikiText-2 测试 NLL 为指标。为放大效应，受控实验用 INT6（生产用 INT8）。结论：单变换各有恢复上限，组合变换（INT6 下 ⟨T,T⟩ 组合，340M 的 Mamba-2 与线性注意力）能恢复约两倍于最佳单变换的超额 NLL。

生产验证：起点是 SSDi8（Kim et al. 2026，Mamba-2 的 INT8 递归 prefill 管线，W4A8 投影）。把 key 侧基变换 R_QK + D_QK 加进 SSDi8，value 侧因细粒度尺度已经足够而不动。WikiText-2 perplexity（表 2）：Mamba-2 1.3B 的量化罚分（对 FP16）从 SSDi8 的 0.508 降到 0.410；2.7B 从 0.381 降到 0.312；8B 从 0.370 降到 0.185，量化罚分砍掉一半以上；Nemotron-H Base 从 0.308 降到 0.145，Reasoning 从 0.498 降到 0.227。延迟：Q-K 变换并入 SSDi8 的量化 scale，prefill 延迟不增（A5000，T=2048）。

边界：不变量族针对线性递归，对 softmax 注意力无效；生产结论绑定 SSDi8 管线与 Mamba-2/Nemotron-H 这两个家族；受控实验的 INT6 是放大手段，生产数字仍是 INT8。

**【一方博客，详】** [Unlocking Tensor Core Performance for Machine Learning Interatomic Potentials](https://developer.nvidia.com/blog/unlocking-tensor-core-performance-for-machine-learning-interatomic-potentials)（NVIDIA Developer Blog，2026-10-29）。与上一篇对读的另一端：做法是 FP32 仿真到低精度张量核心上，精度方向与 LinQuant 相反。

两层方案。BF16x9 面向 Blackwell（cc 10.0/10.3）：cuBLAS 内置的 CUBLAS_EMULATE_SINGLE_PRECISION=1 路径，模型代码零改动，17,280 原子系统的大 GEMM 提速 2.2–2.5×，192 原子小系统 1.2–1.4×；MD 步在 performant 模式 1.7×、eager 1.4×（17,280 原子）。误差低于模型自身的非确定性。TF32x3 面向 Ampere（A100）：CUTLASS 手写，三个乘积项（L×L、L×R、R×L），GEMM 提速 1.7–1.9×；17,280 原子的 26M 参数 PET-MAD 模型 MD 步最高 1.5×；255M 参数大 checkpoint 在 192 原子上 1.4×；力误差约为两次独立 FP32 运行之差的 3 倍（大模型 3.9×10⁻⁶ eV/Å）。

一个超出加速的结论：一阶 TF32（单乘积）在 NVE 积分下能量漂移、轨迹粗糙，TF32x3 保持光滑与能量守恒；539 原子 Cantor 合金晶片的结构弛豫里，TF32x3 在 218–222 步收敛（每步 1.5×），一阶 TF32 跑到 1,000 步仍不达力容差。也就是说低精度仿真里「保不保得住守恒量」和「快不快」是两件事，一阶近似只赢速度。模型是 Point Edge Transformer（PET-MAD 的 26M 与 255M 两档），场景是 MLIP 力场计算，不是 LLM 训练。

**【论文，摘要级】** [Dobb: Shard-Local Preconditioning in Block-Diagonal Eigenbases](https://arxiv.org/abs/2610.39412)（arXiv 2610.39412）。当参数与优化器状态超出单节点内存、张量被 TP/FSDP 分片后，Muon 这类矩阵感知优化器为了跨分片做全局矩阵操作而引入额外通信。Dobb（Distributed Optimizer with Block-diagonal Eigenbases）的摘要级信息：用块对角特征基把预条件化压到分片本地（shard-local），免去全局矩阵操作。摘要级范围：分片本地近似与 Muon 全量版本的收敛差异、通信节省量均未读。

**【论文，摘要级】** [MemSteer: Turning User Histories into Supervision for Agent Memory Optimization](https://arxiv.org/abs/2610.39276)（arXiv 2610.39276）。agent 记忆系统要适应用户历史与任务需求，人工标注监督是现成的指导信号，但新用户的标签稀缺，手工构造 QA 对与支撑证据成本高。MemSteer 把无标签的用户历史直接转成监督信号，用于记忆设计与改进的评估反馈。摘要级范围：转化方法与记忆质量结果未读。

## 工程实践

**【一方博客，详】** Mistral Large 4 开源权重同日双帖：[vLLM 的 serving 全套](https://vllm.ai/blog/2026-10-29-mistral-large-4)（vLLM 团队，2026-10-29）与 [Hugging Face 的模型侧介绍](https://huggingface.co/blog/mistral-large4)（HF 团队与 Mistral，2026-10-29）。同一事件两个第一方视角，数字可互核。

模型侧（HF 帖）：约 1T 总参数、49B 激活、1M 上下文，多模态（Pixtral 编码器，30 层、hidden 2048、patch 14）多语言 MoE。72 层 decoder，首层密集 FFN，其余 71 层每 token 由 softmax 路由选 128 专家中的 4 个，加 1 个常驻 shared expert，共 5 激活。注意力是 MLA + DSA top-k indexer（每 query 保留 2048 个 key，32 个 index head，44 层自带 indexer，28 层复用最近前置层的 top-k；每第 4 层 NoPE，39–71 层 NoPE 读第 35 层 latent KV）。权重 10 月 6 日预览、10 月 29 日开放（第三方报道：Fortune），许可是 Mistral Ecosystem Open-Weight License（MIT 衍生，对以模型服务形式对外提供有限制）。安全：Artificial Analysis Cyber Index 82%（口径是能复现真实漏洞并给出补丁）；JailbreakBench / StrongREJECT / AgentHarm 平均拒绝率高于任何开放权重模型。

服务侧（vLLM 帖）四项。DSpark 投机解码：3 层滑动窗口 MLA 当 drafter（2048 token 窗口、BF16 KV，独立 KV cache group），深度 3，每步接受约 2.9 token（c1 2.90、c32 2.85），TP8 上输出吞吐约 2×。NVFP4 checkpoint（专家 NVFP4，注意力与 shared expert FP8，KV 默认 FP8 latent）：对 FP8 全部任务差距在 2.1 分以内、平均 −0.3，completion token 差在 4% 以内，TP8 decode 快 1.08–1.19×（配 DSpark 1.18–1.22×），KV cache 约 1.5×。DCP（按 token 切 MLA latent KV 的分布式上下文并行）：TP8 的 KV 容量从 2.38M 到 18.88M token（FP8，7.9×），NVFP4 下 3.60M 到 28.76M；DCP8 的 collective 开销从 7 ms/step 优化到 3.2 ms/step，c1 TTFT p50 从 6.89 s 到 4.73 s（60k 输入/1k 输出），c64 输出吞吐 139.1→204.0 tok/s（+47%）。代价：不开投机时 DCP8 每 token decode 比 TP8 慢 16–28%，KV 不是瓶颈时不值。P/D 分离场景里 DSpark 在 8k/32k/60k 输入下接受率 2.98/2.86/2.78，与 P/D 布局无关。PCP+DCP 组合的 prefill 节点 TTFT 最多降 1.6×（5k token prefill profile 里注意力 165 ms→38 ms）。一个 agentic P/D 对照（约 100k token 会话）：TP4+DCP4 的 decode 节点在 32 个并发会话下 TTFT 保持 0.7 s，纯 TP4 节点 KV 耗尽后 TTFT 爬到 15 s。另有 NIXL 的 P/D 分离（DP/EP、TP、PCP×DCP prefill 三种布局）与 AMD MI350 的 day-0 支持（含 DSpark、图像输入、MXFP4 专家 EP）。部署锚点：FP8 8 卡，NVFP4 在 Blackwell 上 4 卡。

本地与托管（HF 帖）：单台 M3 Ultra 上 Q2_K GGUF prefill 约 90 tok/s、生成 15 tok/s；4×RTX 6000 Pro 上 NVFP4 32K 上下文 prefill 130–590 t/s；IQ2_XXS 800K 上下文，短上下文 prefill 500 tok/s、生成 30 tok/s，长上下文 prefill 129 t/s、生成 3 tok/s。Inference Endpoints 8×H200 FP8（TP+EP）131K 上下文：单请求 1K 输入 TTFT 约 0.6 s、生成约 65 tok/s，DSpark 接受时 120–138 tok/s；16K×4 并发 prefill 合计 4,300 tok/s；1000 个 ShareGPT 会话总吞吐约 480 tok/s。两帖均为第一方口径，模型 benchmark 与 serving 数字绑定帖内版本，独立复测待观察。

**【工业博客，详】** [Grace Blackwell needs a new scheduler](https://www.skypilot.ai/blog/grace-blackwell-needs-a-new-scheduler)（SkyPilot 团队，2026-10-29）。这篇是产品发布稿（推 SkyPilot Platform 与 Frontier Trainer），自报数字按方向读，Slurm 模型部分有可独立核对的锚点。

背景数字。NVL72 机架内 72 GPU 走 NVLink fabric，每 GPU 18 个 NVLink 口 × 100 GB/s = 1.8 TB/s 双向，18 颗 NVSwitch，总带宽 130 TB/s 无阻塞；对照 InfiniBand 每方向 400 Gb/s。专家并行 64 路放在 8 卡服务器上要跨节点走 IB，all-to-all 占训练时间最多 60%（引 [arXiv 2603.07685](https://arxiv.org/abs/2603.07685)）；NVL72 把 64 GPU 收进单一 NVLink 域。SemiAnalysis 的 DeepSeek-R1 交互服务测算：GB200 NVL72 的 32 路 EP 对比 8 卡 B200（EP 上限 8），单 GPU 吞吐最高 4.4×。Meta 的 MTBI（mean time between interruptions）报告：千兆瓦级超算上 4 卡节点约 490 天（Meta 工程博客，2026-10-19）；NVL72 把机架变成原子调度单位后，blast radius 按 18× 放大。

核心主张：Slurm 的 fairshare + gang 调度在 NVL72 上不成立，应该按机架切 slice。NVIDIA 自己发布过这套模型的对照（128 机架/2,304 节点集群，不可用率 2% 时 16 节点切片的可用节点 2,037，比 18 节点切片多 27%，比 9 节点切片多 4%；对比 8 节点切片在不可用率 3.3% 之内可用容量损失小于 1%），SkyPilot 把这个模型产品化：拓扑感知调度（每机架一个 slice）、Frontier Trainer 的 in-place 恢复（GPU Manager 故障检测后备件换入）、Auto Defrag（只抢占可 checkpoint 恢复的 job 来腾整机架，交互式开发环境默认豁免）。实测数字：GR00T N1.7 在 512 张 GB300（128 节点）上预训练，机架感知 slice 放置对比朴素跨机架放置，吞吐 +14.4%、迭代时间 1.59 s→1.39 s（NVIDIA GR00T 团队对照，YouTube 发布）；SkyPilot 生产集群（数万客户 GPU，NVL72 生产集群）不可用率约 2%（自报）。HN 132 分 21 评论。
