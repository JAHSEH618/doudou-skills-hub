# 博文与历史编辑

2026-09-29 起按用户要求采用博文阅读形式。先更新本 skill，再编辑当期与历史；发布目标为当前 GitHub Pages。

写作先从本期证据里选一个具体问题。导言说明这个问题为什么把几篇材料连在一起，不宣称发现行业统一趋势。每篇正文解释方法改变了什么、对照是谁、结果多大、哪个条件下不能外推。首推可以展开完整论证，摘要级条目只展开摘要确实支持的内容。额外事实需新增已读原始来源，不能靠语言润色补造事实。

应用 ra-人话 时，删除口号、假设的读者心理、含糊比较和「不是 X 而是 Y」套句。保留事实、数字、证据等级和作者立场。技术附录可用编号核验，长文主体优先用自然段。

博客和 X 有自己的阅读空间。博客优先选择第一方实现细节、作者导读、维护者复盘；X 保留可以核对身份与原帖内容的观点。原帖只有演示或自报数字，就写明尚缺复现条件。没有读到正文的博客不能标全文；没有核到原帖的 X 不能引用具体言论。

历史文章增加内容时，在元数据记录编辑日期，材料旁标原始发布日期。正文不写「本次补充」或扫描说明。新阅读不计入旧扫描数量，不进入原有判断账本的历史证据。若补充发现错误，写明更正内容、理由和日期，不能无声改写旧结论。

所有外链检查 HTTP、重定向和目标内容。403/429/超时只表示当前检查受限。X 核对原帖或官方 oEmbed，搜索索引只作辅助，分别记录。确认失效的辅助链接取消点击并给出原因；主来源失效时寻找 DOI、会议页、作者原文等可靠替代。无可靠主来源的条目移入仓库待核验记录，不继续推荐。链接审计只保存在仓库，不加入文章导航或正文。

页面提供发布日期、编辑日期、阅读时间、文内目录和历史导航。正文按技术问题重组，不显示检索、扫描、核验流程、skill 或生成说明；完整过程只留在仓库记录。首页使用真实主题标题与摘要。图表仅在解释论点时使用，账本通过主导航访问，读者不需要先滚过一屏目录才能开始阅读。无外部字体、无追踪；基本阅读不依赖 JavaScript。
